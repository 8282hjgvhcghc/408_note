## 第一章 综述

### 1. 程序从编译、链接、装载到执行的全过程，以及程序内存映像

#### 考点核心
一段高级语言源程序要变成可运行的进程，必须依次经过 **编译 → 链接 → 装载 → 执行** 四个阶段，最终在内存中形成固定的**内存映像（内存布局）**。

#### 要点拆分

**（1）编译**
把高级语言源程序翻译成汇编或目标模块（.o / .obj）。编译器只保证**一个编译单元内**符号的定位，函数、变量等外部符号还没有确定地址，这就是「地址绑定」尚未发生。编译阶段还可以做**静态编译**（把库代码直接编进程序）与**动态编译/解释**。

**（2）链接**
把若干目标模块装配成一个可执行文件（exe / ELF）。链接的本质是**合并节（section）并重定位符号**，分为**静态链接**和**动态链接**/**装入时动态链接**/**运行时动态链接**。

**（3）装载**
由操作系统（具体是装入程序 Loader）把可执行文件的**代码段、数据段**按重定位的方式放入内存，建立逻辑地址到物理地址的映射。有三种装入方式：**绝对装入**、**静态重定位（可重定位装入）**、**动态重定位（运行时装入）**。

**（4）执行**
程序开始运行，CPU 从入口地址取指执行。执行中会通过**访存指令**访问数据，逻辑地址由 **MMU** 配合页表/段表转换为物理地址。

#### 程序的内存映像（典型布局，由低地址到高地址）
```
┌─────────────────────────────┐ 高地址
│   栈 (Stack)                │  向下增长
│   ↓                         │
│   ······ 空闲 ······        │
│   ↑                         │
│   堆 (Heap)                 │  向上增长
│   .bss（未初始化全局/静态）  │
│   .data（已初始化全局/静态） │
│   .text（代码段 .rodata）    │
└─────────────────────────────┘ 低地址
```

#### 记忆要点
**「编译生成逻辑地址、链接合并节并重定位、装载建立映射、执行配合 MMU 访问」**；内存映像核心是「代码段只读 + 数据段（初始/未初始化）+ 堆 + 栈 + 环境/参数区」。

#### 易错提醒
- **静态链接**生成的程序**可移植性差**但启动快；**动态链接**节省内存、便于更新库，但启动稍慢。
- 链接时**只能确定逻辑地址**，物理地址要到**装入/执行**时才确定（除非绝对装入）。
- .bss 段在可执行文件中**不占磁盘空间**（只记大小），运行时由系统清零。

### 2. CPU 的特权级、用户空间与内核空间、用户栈与内核栈、特权指令

#### 考点核心
CPU 有**特权级（运行状态）**之分：内核态（管态/核心态）与用户态（目态）；程序区分为**用户空间**与**内核空间**；进程有两套栈——**用户栈**与**内核栈**；两类指令——**特权指令**与**非特权指令**。

#### 要点拆分

**（1）特权级 / 运行状态**
- **内核态**：CPU 可以执行**全部指令**（含特权指令）、访问**全部地址空间**。由操作系统核心代码运行。
- **用户态**：只能执行**非特权指令**、不能直接访问内核空间，访问受限硬件（I/O、中断开关等）会触发**陷入/异常**。
- 状态转换：**用户态 → 内核态**只能通过**中断/异常/系统调用（trap 指令）**；**内核态 → 用户态**由内核执行专用指令（如 `iret`、`rte`）返回。

**（2）用户空间与内核空间**
- **用户空间**：进程自己的代码、数据、栈、堆；普通程序在用户态只能访问它。
- **内核空间**：操作系统核心、内核数据结构（PCB、页表等）所在；只有内核态能访问。
- 现代 OS 通过**分页/权限位**对空间进行保护分隔。

**（3）用户栈与内核栈**
- **用户栈**：进程在用户态运行时的局部变量、函数调用现场；位于用户空间。
- **内核栈**：进程进入内核态（系统调用/中断处理）时使用的栈，位于内核空间；保存内核态现场（如寄存器的某部分、系统调用参数、栈指针），**每个进程/线程一个独立内核栈**。
- 目的：**隔离**，防止用户程序破坏内核栈数据；系统调用切换时**切换栈指针**到内核栈。

**（4）特权指令**
- 例如：**I/O 指令（in/out）**、**中断开关（cli/sti）**、**置时钟、修改 PC/PSW、设置页表基址、装入/修改系统寄存器（如 CR3）** 等。
- 关键判断：**凡能改变系统运行状态、访问关键硬件的指令都是特权指令**，只能在**内核态**执行；用户态执行会触发**特权指令错/陷入**。

#### 记忆要点
「内核态管天下、用户态受限；中断/系统调用由低升到高；特权指令只许内核态；用户栈与内核栈相隔离」。

#### 易错提醒
- 用户态**执行特权指令**会产生**异常（约束性异常）**，由 OS 转成信号（如 `SIGSEGV`/`SIGILL` 类），**不是**无条件允许，而是**阻止**。
- **CPU 状态切换 ≠ 进程切换**：用户态↔内核态（模式切换）只改变**特权级**，进程仍在运行（同一进程）；**进程切换**则改了**当前进程**。
- 内核栈是**每进程**的，不是全局的——不同进程进入内核用各自内核栈。

### 3. 中断相关概念和中断全过程

#### 考点核心
中断是 CPU 对外部（或内部）事件作出响应的机制，核心是一套**中断全过程（中断响应 + 中断处理 + 中断返回）**；要区分**中断、异常、陷入**。

#### 要点拆分

**（1）概念分类**
- **中断（外部中断/异步中断）**：由**外部设备**（时钟、键盘、磁盘等）引起，与当前指令**无关**，异步发生。
- **异常（内部中断/同步中断）**：由**当前指令执行**引起，同步，如**缺页、除零、非法指令、越权访问**。
- **陷入（trap）**：**系统调用**导致，由用户程序**主动**执行 `trap`/`syscall` 指令产生，属于**程序性中断**，是用户态进入内核态的唯一途径。

**（2）中断全过程（响应到处理）**
1. **检测中断**：CPU 在**每条指令执行结束时**采样中断请求（中断屏蔽寄存器的状态）。
2. **关中断**：响应中断时**自动关中断**，防止在保存现场时被更高优先级中断打断（可屏蔽中断）。
3. **保存断点（现场）**：把**程序计数器 PC 和程序状态字 PSW**（关键寄存器）压入内核栈，保存现场。
4. **找到中断向量/服务程序**：根据**中断向量号**查中断向量表，得到中断服务程序入口地址。
5. **进入中断服务程序**：保存其余通用寄存器等上下文，转入内核态，执行中断处理逻辑。
6. **恢复现场、开中断**：处理完恢复现场，**开中断**，执行 `iret`/`rte` 返回断点继续原程序。

#### 记忆要点
「指令结束后采样 → 关中断 → 保存断点 → 查向量表 → 进服务程序 → 恢复现场、开中断、返回」。

#### 易错提醒
- **开/关中断**是**特权操作**，只在**内核态**完成。
- 中断发生时，CPU 可能是**用户态**，中断处理会让 CPU **升为内核态**。
- 区分：**外部中断异步**（与指令无关）、**异常同步**（由指令引起）；二者编址机制不同（中断向量 vs 异常向量可能共用）。

### 4. 系统调用全过程（逐步分析每一步做了什么、利用了什么机制）

#### 考点核心
系统调用是**用户程序请求操作系统服务**的接口，利用**陷入（trap）机制**从用户态切换到内核态。全过程要逐步拆解「陷进 → 处理 → 返回」。

#### 要点拆分

**（1）用户态准备**
用户程序调用库函数（如 `read`），库函数把系统调用号放入**寄存器**（如 Linux 的 `eax`/`r7`），参数放入**寄存器**（如 `ebx...`/`r0-r5`）或**栈**。不是直接调内核函数。

**（2）执行陷入指令**
执行 `trap`/`syscall`/`int 0x80` 指令 → CPU 检测到从用户态请求服务 → 触发**陷阱中断**。

**（3）状态切换与内核栈切换**
- CPU **升为内核态**。
- 把**栈指针**从用户栈切换到该进程的**内核栈**。
- 保存用户态现场（PC/PSW/通用寄存器等）到内核栈。

**（4）查系统调用表**
内核根据**系统调用号**到**系统调用表**（system call table）中查得对应的**内核服务函数入口**。

**（5）内核执行服务**
内核在**内核态**执行该服务（如 read 的驱动操作），利用内核数据结构与硬件（I/O 等）；必要时**检查参数合法性、权限**（如地址是否越界）。

**（6）处理结果并返回**
内核把结果放入**寄存器**，恢复用户态现场，**降为用户态**，`iret` 返回用户程序，库函数把返回值返回给调用者。

#### 记忆要点
「库函数封装 → 陷入指令 → 升内核/切内核栈/存现场 → 查系统调用表 → 内核执行 → 存结果降级返回」。利用的机制核心是：**陷入（trap）+ 特权级切换 + 内核栈 + 系统调用表 + 参数寄存器/栈传递**。

#### 易错提醒
- 系统调用必须经**陷入**，**不能直接调用**内核代码（否则破坏保护和状态）。
- **系统调用是程序主动的、受控的**；而**缺页中断是异常**（也是提升为内核态的一种方式，但机制不同）。
- 系统调用**每次都要切换特权级和栈**，因此**开销大**，所以才有「减少系统调用次数」的优化。

### 5. 两类虚拟机的概念和特征

#### 考点核心
**虚拟机（VM）**指用软件模拟一台完整计算机，主要分**系统虚拟机**与**进程虚拟机**两类。

#### 要点拆分

**（1）系统虚拟机（System VM，如 VMware、VirtualBox、KVM）**
- 目标：在**一台物理机**上同时运行**多个完整的操作系统**（每个 VM 有自己独立的 OS、虚拟 CPU/内存/外设）。
- **VMM（虚拟机监视器/Hypervisor）**负责划分硬件资源并隔离多个 VM。
- 特征：**强隔离、硬件级虚拟**；一个 VM 崩溃不影响其它；资源共享但看重可用性与隔离性。
- 分**类型 1（裸金属 Hypervisor）**与**类型 2（宿主型）**。

**（2）进程虚拟机（Process VM，如 JVM、P/VM、JIT 虚拟机）**
- 目标：为一个**应用程序/进程**模拟出一个**与硬件/平台无关的虚拟指令集环境**（如 Java 字节码 + JVM）。
- 特征：**跨平台、一次编译处处运行**；虚拟的是**单一进程**，不虚拟完整 OS。
- 编译/解释执行字节码，可做**即时编译（JIT）**优化。

#### 记忆要点
「系统 VM 虚拟整个 OS、多 OS 并行、看重隔离；进程 VM 虚拟单个进程环境、看重跨平台」。核心是**Hypervisor / VMM 划分硬件资源**以及**虚拟指令集与运行时**。

#### 易错提醒
- 系统 VM 的 OS **不知道自己运行在 VM 上**（对 Guest OS 透明）；进程 VM（如 JVM）对外是普通进程。
- VMM 需要**同时运行在最高特权级**（VMX/SVM 硬件虚拟化支持）与 Guest OS 的特权级隔离，通常依赖 CPU **虚拟化扩展**（Intel VT-x / AMD-V）。

### 6. 操作系统有哪些发展阶段？分别有什么特点？

#### 考点核心
操作系统的发展按**批处理 → 分时 → 实时 → 网络/分布式/微机**大致演进，各阶段特点围绕「**资源利用率、响应时间、交互性、实时性、多用户多任务**」展开。

#### 要点拆分

1. **手工操作阶段（无 OS）**：人直接操作，CPU 空闲多，利用率极低。
2. **单道批处理系统**：内存只放一道作业，**顺序执行**，解决了人机矛盾但**CPU 利用率低**（I/O 时 CPU 空转）。
3. **多道批处理系统**：内存同时放多道作业，**并发执行**，显著**提高 CPU、内存、I/O 利用率**；但**无交互**、平均周转时长。
4. **分时操作系统（Time-sharing）**：把 CPU 时间**按时间片轮流**分配给多个用户，**交互性好、多用户、及时响应**；典型如 UNIX。
5. **实时操作系统（RTOS）**：对外部事件在**规定时间内**作出响应，**确定性、可靠**；分**硬实时**（必须满足时限，如导弹控制）与**软实时**（尽量满足，如多媒体）。
6. **网络操作系统**：支持**网络通信与资源共享**，面向多机互联。
7. **分布式操作系统**：多机**资源共享 + 并行**，对用户**透明**成"一台机器"；强调**容错、可扩展**。
8. **微机/嵌入式操作系统 & 新一代 OS**：Windows/Linux 等面向通用；嵌入式 OS 面向特定设备、**实时/资源受限**。

#### 记忆要点
「手工→单道批→多道批→分时→实时→网络→分布式」。主线：**从提高利用率 → 到交互 → 到实时**。

#### 易错提醒
- **批处理**主打**资源利用率高**，但**无交互**；**分时**主打**交互与及时性**，以**时间片轮转**为核心；**实时**主打**确定性响应**。
- 分时与多道批处理都是**多道**，区别在**交互/响应目标**。

### 7. 操作系统引导的全过程（从开机到操作系统接管计算机）

#### 考点核心
引导（Booting）是**从上电/复位到 OS 内核接管、用户程序可运行**的完整过程。核心步骤：**ROM 固件 → BIOS/UEFI → 引导程序 → 加载 OS 内核 → 初始化 → 就绪**。

#### 要点拆分

1. **上电复位**：CPU 从**固定地址**（如 0xFFFF0 / reset vector）取第一条指令，执行 **ROM（固件 BIOS/UEFI）**中的自检代码。
2. **加电自检（POST）**：BIOS 检查 CPU、内存、键盘等基本硬件是否正常。
3. **BIOS/UEFI 初始化**：初始化基本设备，建立**中断向量表**（BIOS 中断），**引导自举**。
4. **读取引导扇区（MBR/引导块）**：BIOS 读**磁盘第一个扇区**（MBR，含引导程序 + 分区表），把控制权交给**引导程序（bootloader，如 GRUB）**。
5. **引导程序加载 OS 内核**：bootloader 从磁盘把 **OS 内核映像**装入内存（或先加载更小的引导管理程序），并准备**内核启动参数**。
6. **进入内核态初始化**：OS 内核接管，**设置 GDT/IDT、页表、内存管理、中断/异常处理**，初始化各子系统（进程管理、I/O、文件系统、设备驱动）。
7. **创建第一个用户进程**（如 init / systemd），建立用户态环境。
8. **系统就绪**：显示登录/桌面，等待用户使用。

#### 记忆要点
「上电复位 → POST → BIOS/UEFI → 读 MBR/引导块 → bootloader 加载内核 → 内核初始化 → 创建 init → 就绪」。关键词：**固件自举、引导块、bootloader、内核初始化、init 进程**。

#### 易错提醒
- **BIOS** 只在开机时起作用，提供**物理地址**访问，**不能运行在保护模式**；**bootloader** 负责把内核装入**内存高位**（常在保护模式下）。
- 现代 UEFI 取代 BIOS，但**引导骨架不变**。
- 引导全程是**内核态**逐渐接管的过程；**第一个用户进程**由内核创建。

---

### 8. 微内核和外核的概念和特点

#### 考点核心
这是**操作系统体系结构**的两种设计。**微内核**把内核最小化，大量服务移到用户态；**外核**让应用程序直接管理自己的物理资源。

#### 要点拆分

**（1）微内核（Microkernel）**
- 概念：把**内核做得很小**，只保留**最基本的机制**：**进程间通信（IPC）、线程/进程管理、低级内存管理（地址空间）、中断/异常处理**等核心功能；把**文件系统、设备驱动、网络协议栈**等尽量放到**用户态**作为服务进程。
- 特点：**内核小、可靠性高**（服务崩溃不影响内核）、**可移植/可扩展、安全性好**；但 **IPC（消息传递）开销大**，性能可能下降。
- 代表：Minix、QNX，以及 macOS（混合、部分借鉴）、Windows NT 内核（微内核思想，实际为混合）。

**（2）外核（Exokernel）**
- 概念：内核只负责**安全地分配物理资源**（CPU、内存、磁盘），**不做资源的高级抽象/管理**，把**资源的管理与保护策略**下放给**应用程序库（library OS）**。
- 特点：**灵活、少抽象、减少内核层**，能给应用**高性能**（应用自己定制内存管理、文件系统）；但**可移植性差、编写复杂、安全性依赖内核提供的资源分配机制**。
- 代表：Exokernel 研究原型。

#### 记忆要点
「微内核：内核最小、服务放用户态、靠 IPC、可靠但开销大；外核：只做资源安全分配、应用自己管资源、灵活高性能、可移植性差」。

#### 易错提醒
- **微内核 ≠ 宏内核（单内核）**：Linux 是宏内核（支持模块），Windows NT 是**混合内核**；微内核全部服务用户态，需大量 IPC。
- **外核与微内核不同**：外核几乎不做抽象（把管理权交给库 OS 层），微内核保留最基本的抽象但把服务移到用户态。

## 第二章 进程管理

### 1. 请描述什么是进程，构成进程的主要有哪些组成部分？

**核心定义**：进程是**程序在一个数据集合上的一次运行过程**，是系统进行**资源分配**和**调度**的一个独立单位；它具有**动态性、并发性、独立性、异步性、结构性**。

**组成（进程的构成 = 程序段 + 数据段 + PCB）**：
- **程序段**：进程中能被进程调度执行的代码（算法的描述）。
- **数据段**：进程运行时所需的数据、变量、工作区（即程序的数据集合）。
- **PCB（进程控制块/进程描述符）**：进程存在的唯一标志，存放**进程描述信息、控制信息、资源信息、现场信息**等，是操作系统管理进程的依据。

**记忆要点**：进程 = **程序 + 数据 + PCB**。程序是**静态**的，进程是**动态**的；进程是**活的**，程序是**死的**。

**易错**：进程与程序的**根本区别**：进程是动态的、有生命周期的；一个程序可以被多个进程共享（多个进程可对应同一程序）。

---

### 2. 如何理解进程地址空间？

**核心**：进程**地址空间**是进程在**虚拟地址**中所能访问的所有**逻辑地址**的集合（即进程看到的"内存"），它是**逻辑上独立**、由操作系统管理的一张**虚拟内存映射**。

**要点**：
- 每个进程都有**自己独立的虚拟地址空间**，它们**互不冲突**（通过**页表**映射到不同的物理地址）。
- 逻辑地址空间包括：**代码段、数据段 .data、.bss、堆、栈、环境/参数区**（见综述内存映像）。
- **地址空间 ≠ 物理空间**：逻辑到物理的映射由 **MMU + 页表/段表** 完成；进程看到连续地址，物理上可分散。
- **地址空间大小**受**机器字长**决定（如 32 位为 4GB，64 位更大），与物理内存**大小无关**（虚拟存储）。
- **隔离**：一个进程不能访问另一个进程的地址空间，靠**页表 + 权限**保护。

**易错**：进程地址空间是**虚拟**的，不是物理的；进程"占多少内存"与其地址空间大小是两回事（可能只装入一部分，产生缺页）。

---

### 3. 进程控制块（PCB）的作用和组织方式

**作用**：PCB 用于**描述和控制进程**，是进程存在的唯一标志。操作系统通过 PCB 来**登记进程信息、管理进程状态、进行调度、分配资源**。PCB 在**创建进程**时建立，在**进程终止**时回收。

**PCB 主要内容**：
- **进程标识符（PID）**：唯一的进程号，含父进程 PID、用户标识等。
- **处理机状态（现场）**：通用寄存器、PC、PSW、栈指针等（用于**进程切换**恢复现场）。
- **进程调度信息**：进程**状态、优先级、调度参数、其它调度信息**（如等待时间）。
- **进程控制信息**：**程序段/数据段地址、进程同步/通信机制、资源清单、链接指针**等。

**组织方式**：
- **链表方式**：按状态（就绪、阻塞…）把同状态进程的 PCB 串成**链表**（就绪队列、阻塞队列等）。**优点**：动态、灵活；**缺点**：查找/修改需遍历。
- **索引表方式**：为每种状态建立一个**索引表**，表中记录 PCB 地址；各状态索引表构成数组。**优点**：查找快；**缺点**：需额外空间、索引表有限。

**记忆**：「PCB 是进程的唯一标志；内容=标识符+现场+调度信息+控制信息；组织=按状态链表或索引表」。

---

### 4. 内核与进程的地址空间的关系是什么样的？

**核心**：现代操作系统把**内核空间**与**用户空间**分开，但**所有进程**都**共享同一份内核空间**，只是各自拥有独立的用户空间。

**要点**：
- **共享内核空间**：所有进程的**高端内存区域**（如 3GB~4GB，Linux 的 0xc0000000 以上）映射到**同一物理内核**，进程处于**内核态**时可访问内核代码/数据结构。
- **独立用户空间**：每个进程的**低端区域**（用户区）互不相同，通过各自**页表**映射到不同物理页面，保证**隔离**。
- **状态决定访问权限**：**用户态**只能访问**用户空间**；**内核态**可访问**整个地址空间**（内核 + 用户）。
- 因此**进程切换**时，用户空间变了（切换页表基址），但**内核空间部分不变**（同一份）。
- 好处：**内核数据结构全局唯一**（如 PCB、文件表全校共享），进程通过系统调用进入内核访问。

**易错**：进程的**内核空间是共享的**，不是每进程一份；切换页表时内核部分不变，所以上下文切换能复用内核映射。

---

### 5. 五进程状态模型，各状态之间如何转化？转化条件是什么？

**核心**：**创建（新建）→ 就绪 → 运行 → 阻塞 → 终止**五个状态；就绪↔运行、运行↔阻塞、就绪→运行、阻塞→就绪等转换都要满足**特定条件**。

**五状态及转换**：
```
                     I/O完成/事件发生(唤醒)
     ┌─── 阻塞 ───────────────┐
     │        ▲                │
创建 → 就绪 ──→ 运行 ──→ 终止
       ▲     ▲ │   │
     (调度)  │ │   │ 时间片/被抢占
            │ └──(等待事件/I-O)──┐
            │                   │
            └──── I/O完成 ──────┘
```

**各转换及条件**：
1. **创建 → 就绪**：进程已创建并分配资源，进入**就绪队列**等待调度（创建后即可运行但它还没被调度）。
2. **就绪 → 运行**：**进程被调度**（分配 CPU）。条件是**就绪队列非空且 CPU 空闲/选中该进程**。
3. **运行 → 就绪**：**时间片用完**或**被更高优先级抢占**；进程**被迫**让出 CPU，回到**就绪**队列。
4. **运行 → 阻塞**：进程**发生 I/O、等待资源、等待事件**（如等待信号量、等待输入）而无法立即继续；**只有进程自身知道何时阻塞**。
5. **阻塞 → 就绪**：**等待的事件发生、I/O 完成、所需资源被满足**，由**其它进程/操作系统**唤醒；此时才**进入就绪**队列（要先就绪、再被调度运行）。
6. **运行/就绪/阻塞 → 终止**：进程**正常结束/异常/被剥夺**，转入终止状态，回收资源。

**记忆要点**：
- **运行 → 就绪**：主动让出（时间片/抢占）；**运行 → 阻塞**：被迫等待；**阻塞 → 就绪**：等的事件到了（被唤醒，但**不能直接运行**，要先就绪）。
- **就绪 → 运行**是**调度**；**阻塞 → 就绪**是**唤醒**；二者不同（唤醒≠调度）。

**易错**：进程被唤醒后是进入**就绪**态，**不直接运行**，必须再次被调度；**阻塞只能由进程自己知道，唤醒只能由别人（OS/其它进程）**。

### 6. 七进程状态模型相比五进程状态模型有什么区别？增加了哪些状态转化？

**核心**：七状态模型在**五状态**基础上增加了**「创建」和「终止」**的细化，或者更准确地说是增加了**「静止就绪（挂起就绪）」与「静止阻塞（挂起阻塞）」**两个**挂起**状态，把**就绪/阻塞**细化为**活跃**与**静止**两套。

**七状态**：**创建、就绪、运行、阻塞、终止** + **静止就绪（挂起就绪）、静止阻塞（挂起阻塞）**。即：把"**挂起（Suspend）**"引入，区分**活跃/静止**。

**区别与新增转换**：
- **增加状态**：`就绪 → 静止就绪`（**进程挂起**）与 `静止就绪 → 就绪`（**激活**）；`阻塞 → 静止阻塞`（**挂起**）与 `静止阻塞 → 就绪`（**激活唤醒**）。
- **新增转换条件**：
  1. **就绪 → 静止就绪**：进程**被挂起**（如被父进程/OS 调出内存，内存不足、调试暂停等）。
  2. **静止就绪 → 就绪**：**激活**（如内存充足或用户请求恢复）。
  3. **阻塞 → 静止阻塞**：**挂起**。
  4. **静止阻塞 → 就绪**：**等待事件发生 + 被激活**（唤醒）。
  5. **运行 → 静止就绪**：运行进程被挂起（直接挂起就绪，若内存被换出则调出）。
- **五状态**没有挂起机制，进程要么就绪/运行/阻塞（都在内存），无法被**调出内存**；**七状态**允许进程被**换出（挂起）**到磁盘，缓解内存压力。

**记忆**：「七状态 = 五状态 + 静止就绪/静止阻塞（挂起）；挂起是与内存相关的状态，把进程调出内存；激活/挂起是新增的转换」。

**易错**：**挂起（调出内存）**与**阻塞（等待事件）**是**两个不同维度**；一个进程可同时处于"**阻塞且挂起**"（静止阻塞）。挂起是**进程被调出内存**，阻塞是**等待事件**。

### 7. 用户进程切换全过程

**核心**：用户进程切换 = **内核态**下的**上下文切换（Context Switch）**，即**保存当前进程现场，装入新进程现场**，完成从运行进程 A 切换到进程 B。

**全过程（内核控制）**：
1. **进入内核**：进程切换只能发生在**内核态**（由中断/异常/系统调用触发进入内核）。
2. **保存当前进程现场**：把当前进程（A）的**CPU 现场**（通用寄存器、PC、PSW、栈指针等）保存到其 **PCB** 中；保存**调度相关信息**（状态改、记录时间等）。
3. **选定新进程**：调度程序按**调度算法**从**就绪队列**选一个进程（B）。
4. **更新调度数据**：当前进程 A 状态改为**就绪/阻塞**，新进程 B 状态改为**运行**；更新队列指针、时钟等。
5. **恢复新进程现场**：把 B 的 PCB 中的现场**装入 CPU 寄存器**（恢复 PC、PSW、栈指针等），**切换页表**（若换地址空间）。
6. **返回用户态**：**切换线程/进程上下文**，CPU 转入 B 的用户态继续执行（通过 iret/恢复现场跳转）。

**记忆要点**：「进内核 → 存 A 现场到 PCB → 调度选 B → 改状态/队 → 恢复 B 现场 → 回用户态」。核心是**保存与恢复现场**与**切换地址空间（页表）**。

**易错**：进程切换一定发生于**内核态**，且需要**保存恢复现场**与**切换用户空间（页表）**，因此**开销大**；而**线程切换**若同进程则**不必切换地址空间**，开销小。**模式切换（用户态↔内核态）不是进程切换**（特权级变，进程不变）。

### 8. 进程创建、终止、阻塞、唤醒全过程

**（1）进程创建**
- **触发**：系统初始化、用户请求、作业调度、父进程创建子进程。
- **步骤**：申请 PCB → 分配资源（内存等）→ 初始化 PCB（PID、状态=创建/就绪、现场等）→ 把 PCB 插入**就绪队列**（或建立进程）
- **原语**：`fork` 等。

**（2）进程终止**
- **触发**：正常结束（main 返回/exit）、异常（越界、非法指令、I/O 失败、超时）、外界干预（OS/父进程）。
- **步骤**：找到 PCB → 撤销子进程（若需要）→ 由子进程向父进程回收资源 → 回收 PCB，状态 → 终止/释放。
- **原语**：`exit` 等。**终止的实质是收回 PCB**。

**（3）进程阻塞**
- **触发**：进程**等待资源/事件**（申请资源未满足、等待 I/O、等待信号量、等待输入）而自己暂停。
- **步骤**：进程将当前状态改为**阻塞**，把 PCB 插入**阻塞队列**，**释放 CPU**（交出处理机），保存现场。
- **原语**：`block`。注意：**阻塞是进程主动（自知）的**。

**（4）进程唤醒**
- **触发**：进程**等待的事件/I-O 完成/资源可用**（由**其它进程或 OS** 唤醒）。
- **步骤**：把阻塞进程从**阻塞队列**摘除，状态改为**就绪**，插入**就绪队列**。
- **原语**：`wakeup`。注意：**唤醒是被动的（由别人完成）**。

**记忆**：「创建=申请PCB/分配资源/入就绪；终止=收回PCB/回收资源；阻塞=自己让出CPU/入阻塞队列；唤醒=别人摘除阻塞/入就绪」。

**易错**：**阻塞主动、唤醒被动**；阻塞后进程**进入阻塞队列**，唤醒后**进入就绪队列**（不能直接运行）。

### 9. 父进程与子进程的关系，哪些共享哪些不共享？

**核心**：进程树关系——父进程创建子进程；**父子在逻辑上独立**（各自拥有地址空间、PCB），但**共享部分资源**（打开的文件、部分内存资源等）。

**共享的**：
- **打开的文件/文件描述符**（fork 后子进程继承父进程的已打开文件表项，引用计数 +1）。
- **某些资源**（受 OS 限制，如计算资源的继承、部分控制信息）。
- **系统资源（如 I/O 设备经继承句柄）**。
- 实际上 fork 采用**写时复制（COW）**：**逻辑上共享**物理页面，**读写时才复制**，所以起父子的**逻辑地址空间是独立的**，但**初始共用物理页**。

**不共享的**：
- **地址空间**（代码、数据、堆、栈**逻辑独立**；即使初始内容相同，也是**各自**的地址空间）。
- **PCB**（父子各自独立，PID 不同）。
- **进程状态、执行结束状态、父进程标识**等。
- 子进程对变量、数据段的改动**不影响**父进程（除了 COW 前的初始拷贝）。

**记忆**：「父子共享=打开文件、部分资源、初始物理页（COW）；不共享=地址空间、PCB、状态；fork 后子进程从返回点继续（返回 0，父返回子 PID），各自运行」。

**易错**：`fork` 后父子**并发**执行、**地址复制**（写时复制）而非共享地址空间；父子返回不同值（子是 0，父是子 PID），用于区分执行路径。

### 10. 用户级线程、内核级线程的概念、实现方式、特点

**（1）用户级线程（ULT）**
- 概念：由**用户空间的线程库**（如 pthreads 用户态实现）管理，**内核不知道线程存在**（内核只见一个进程/一个线程）。
- 实现：内核只调度**进程**（TCB 在用户态，线程切换在用户态完成，不陷内核）。
- 特点：**切换快**（不陷内核）、**与内核无关/可移植**；但**一个线程阻塞会阻塞整个进程**（内核把整个进程阻塞），不能利用多处理器并行。

**（2）内核级线程（KLT）**
- 概念：线程由**内核创建和管理**，**内核看到每个线程**，有其 TCB（在内核态）。
- 实现：内核按线程调度，切换需**陷内核**，保存/恢复现场。
- 特点：**一个线程阻塞不影响其它线程**（各自被调度）、**支持多处理器并行**、实时性好；但**切换开销大**、需内核支持。

**记忆**：「ULT 由用户库管理、内核无感知、切换快但线程阻塞拖垮整进程、不能真并行；KLT 内核感知、每条线程被独立调度、能并行、开销大」。

**易错**：**用户级线程的"阻塞"**会阻塞整个进程（内核不知道有其它线程）；内核级线程之间才能**真正并行**（多核）。现代 OS（如 Linux）多用**内核级线程**。

---

### 11. 多线程模型：一对一、多对一、多对多模型的特点

**核心**：线程模型描述**用户级线程与内核级线程的映射关系**。

**（1）一对一模型**
- 一个**用户线程**对应一个**内核线程**。
- 特点：**并发性好**（一条线程阻塞不影响其它）、**支持多处理器**；但**开销较大**（每个线程需内核线程支持）。

**（2）多对一模型**
- 多个**用户线程**映射到一个**内核线程**。
- 特点：**开销小、切换快**（内核只管理一个）；但**一个线程阻塞会阻塞整个进程**、**不能真正并行利用多核**。

**（3）多对多模型**
- 多个**用户线程**映射到**多个（但更少的）内核线程**。
- 特点：**结合两者优点**——既**并发并行**（多条内线并行）又不至于内核线程过多；调度灵活、冲突少。是**折中优化**。

**记忆**：「一对一：一条用户线程一条内核线程（并行好，开销大）；多对一：多条用户线程一条内核线程（快但阻塞拖船、不能并行）；多对多：多条对多条（平衡）」。

**易错**：**多对一**的致命缺点——内核只看到一个线程，一个线程阻塞则整个进程（所有线程）都被挂起。

---

### 12. 共享存储系统怎么实现的？多进程共享内存的过程和相关系统调用？内核如何共享？

**核心**：共享存储（共享内存）是最快的一种 IPC，通过**映射同一块物理内存**到多个进程的地址空间实现**零拷贝、直接访问**。

**实现**：
- 在**物理内存**中划出一块**共享内存区**，把它映射到**多个进程的虚拟地址空间**（各自一个映射项指向同一物理页）。
- 进程**直接读写**自己的映射地址即可交换数据，**无需拷贝**、无系统调用（除同步）。

**多进程共享内存过程 + 系统调用（以 Linux/POSIX 为例）**：
1. `shmget`（或 `mmap`/`shm_open`）：**创建/获取**共享内存段，返回标识符 `shmid`。
2. `shmat`（或 `mmap`）：把共享内存**附接到本进程**地址空间，返回**映射地址**。
3. 各进程通过该**地址读写**（需信号量/互斥锁同步）。
4. `shmdt`：**脱离**；`shmctl`：**删除/控制**。

**内核如何共享**：
- 内核维护**共享内存段**的**页表项**，让多个进程的对应**虚拟页**映射到**同一个物理页**；通过引用计数管理何时可真正回收。
- 共享内存**需要同步机制**（信号量、锁），否则会竞态。

**记忆**：「共享内存=多进程映射同一物理页、直接读写最快、需要同步；调用：shmget/shmat/shmdt/shmctl（或 mmap）」。

**易错**：共享内存**本身不提供同步**，必须配合**信号量/锁**；它是**无拷贝**、速度最快的 IPC 方式，但**缺乏自动同步**。

---

### 13. 消息传递系统的概念、分类、特点

**核心**：消息传递是进程间传送**结构化消息（报文）**以通信，**不依赖共享变量**，适合**分布式/异构**环境。

**分类**：
- **直接通信**：进程**直接指名**发送/接收对象（`send(P, message)` / `receive(Q, message)`）；有**对称**（双方指名）与**非对称**（只发送方指名接收方）。
- **间接通信**：消息经**中间实体（信箱/mailbox）**，发送方投入信箱，接收方从信箱取；**解耦**（发送方不必知道接收方，反之亦然）。信箱又分**容量**（绑定、不限、有/无）、**所有权**（进程所有/OS 所有）等。

**特点**：
- 通信**不受共享内存限制**，可跨机、跨网络，**可靠、灵活、易扩展**。
- 需要**同步**：发送/接收可能是**阻塞**或**非阻塞**（是否等待）。
- 消息传递通常**有边界**（消息是离散单元）。
- **代价**：需拷贝、系统调用开销，比共享内存慢。

**记忆**：「直接通信=指名道姓；间接通信=经信箱中转、解耦；特点=跨机扩展、需同步、有开销」。

**易错**：消息传递是**离散消息**传递（有消息边界），与**字节流**（管道）不同；**间接通信**通过邮箱解耦，适合**生产者-消费者**。

---

### 14. 管道通信的实现方式、读写权限、通信方式、特点

**核心**：管道（pipe）是**半双工**的**字节流**通信，连接一个**读端**一个**写端**，基于**内核缓冲区**实现。

**实现方式**：
- 创建管道（`pipe`）得到**两个文件描述符**：`fd[0]`（读端）、`fd[1]`（写端），指向内核的**环形缓冲区**。
- **读写**：写端把数据写入**管道缓冲区**；读端从缓冲区读出。管道是**字节流**，无消息边界。
- 匿名管道（pipe）用于**父子进程**间（fork 后共享）；**命名管道（FIFO）**用于**不相关进程**间（有对应文件）。

**读写权限**：
- **只能**一端读、一端写：`fd[0]` 读、`fd[1]` 写；管道是**单向（半双工）**，若要双向需用**两个管道**。

**通信方式**：
- 写入数据到管道缓冲区，读出端从缓冲区取；**一旦读出就删除**（数据不能回读）。
- 当**读端关闭**时，写端写会触发 **SIGPIPE**；当**写端关闭/无数据**时，读端读到 **EOF**（read 返回 0）。

**特点**：
- **半双工、字节流、无边界、先进先出**。
- **有缓冲区**（容量有限，写满阻塞），**读写同步**由内核管理。
- **单向**；适合生产者-消费者。

**记忆**：「管道=读端+写端+内核环形缓冲、字节流单向半双工、FIFO；匿名用于父子、命名(FIFO)用于不相关进程」。

**易错**：管道是**半双工**（单向）；**读端关——写端收到 SIGPIPE**；**写端关/无数据——读端 EOF**；管道是**字节流**，**没有消息边界**。

### 15. 信号相关问题：类型、接收与屏蔽、检测时机、用户自定义信号

**（1）信号的类型**
- 信号是**软件中断**，用于通知进程发生了**异步事件**（如 `SIGINT` Ctrl+C、`SIGKILL` 强杀、`SIGSEGV` 越界、`SIGPIPE`、`SIGALRM` 定时、`SIGCHLD` 子进程结束）。
- 有**标准信号**（1~31，可能丢失）与**实时信号**（排队、可靠）。

**（2）信号的接收方式和屏蔽方式**
- **接收**：进程对某信号**默认处理**（如终止、忽略）、**捕获**（自定义处理函数）、**忽略**。
- **屏蔽**：进程用 `sigprocmask`（/`pthread_sigmask`）设置**信号屏蔽集**，屏蔽的信号**暂时不递送**、**排队**，直到解除屏蔽才处理。进程还可把信号**加入阻塞集合**。
- 信号发送用 `kill`/`sigqueue`/`raise`。

**（3）信号的检测时机**
- 进程在**从内核态返回用户态时**（或指定的检查点）**检测信号**是否待处理；通常在内核**返回用户态前**、以及进程**被调度运行前**检查。
- 是**异步**的：信号随时可产生，但**递送/处理**发生在**检测点**。

**（4）用户自定义信号**
- **概念**：用户可为某信号**注册**自己的处理函数，替代系统默认行为。
- **注册**：`signal(signum, handler)` / `sigaction(signum, &act, ...)` 注册/设置处理函数。
- **处理过程**：信号产生 → 排队(屏蔽时) → 在检测点**递送** → 内核把用户态**切换到信号处理函数**（保存现场）→ 执行处理函数 → 恢复现场继续原程序。
- 注意：**`SIGKILL`、`SIGSTOP` 不能被捕获/忽略/屏蔽**。

**记忆**：「信号=软件中断、异步；接收=默认/捕获/忽略，屏蔽=暂时搁置排队；检测时机=内核返回用户态时；自定义=signal/sigaction 注册、处理时切到处理函数」。

**易错**：**SIGKILL/SIGSTOP 不可捕获不可忽略**；信号是**异步**事件，处理时机在**内核返回用户态**的检查点；信号**可能丢失**（标准信号）。

### 16. 调度的不同层次

**核心**：按**调度的对象/粒度**，调度分**高级、中级、低级（进程/处理机）**三层。

**（1）高级调度（作业调度）**
- 按**作业**为单位，从**外存后备队列**选作业装入内存，创建进程，建立 PCB。决定**作业**何时进入内存、成为就绪进程。
- 频率**低**；主要提高**资源利用率**（吞吐）。

**（2）中级调度（内存调度/平衡调度）**
- 按**进程**为单位，在**内存紧张**时把某些进程**换出（挂起）**到磁盘，需要时**换入**。决定**哪些进程调入/调出内存**。
- 对应**七状态模型**的**挂起/激活**。主要**缓解内存压力、提高内存利用率**。

**（3）低级调度（进程/处理机调度）**
- 按**进程/线程**为单位，从**就绪队列**选一个进程**分配 CPU**。决定**哪个就绪进程获得处理机**。
- 频率**最高**；最常说的"调度"通常即指它。

**记忆**：「高级=作业入内存；中级=进程换入换出内存；低级=分配 CPU 给就绪进程」。**频率：低 → 中 → 高**。

**易错**：**中级调度**引入**挂起**（进程调出内存），是内存与进程状态的关系；高级调度对象是**作业**（非进程），低级调度对象是**进程/线程**。

---

### 17. 处理器调度的概念、闲逛进程

**（1）处理器调度的概念**
- **处理机调度（CPU 调度）**：在**多道程序**系统中，按照某种**算法**从**就绪队列**选择一个进程，把**处理机**分配给它运行。目的是提高 CPU 利用率、公平、响应等。
- 调度发生在**调度时机**（进程主动让出/被抢占、时间片到等），由**调度程序**完成选择，**分派程序**完成切换。

**（2）闲逛进程（Idle Process）**
- 当**就绪队列为空**（没有可运行进程）时，系统会运行**闲逛进程（空闲进程）**，它**优先级最低**，**只做空转**（如 `hlt` 指令）等待新进程。
- **特点**：当且仅当**无进程可运行时**才运行；用于让 CPU 有事情可做（避免空转忙等）、维持系统运行；它**不会阻塞**、**不会被换出**，可能在**任何优先级**之下。

**记忆**：「处理机调度=从就绪队列按算法选进程分配 CPU；闲逛进程=就绪队列空时才运行的最优优先级进程、只空转」。

**易错**：闲逛进程**不是被阻塞**，只是**无进程可调度**；它占 CPU 但**永远让位于就绪进程**。

---

### 18. 非抢占式调度的特点

**核心**：**非抢占式调度**下，**一旦某进程获得处理机，就一直运行**直到它**主动放弃**（阻塞、结束），**除非它自己让出**，否则**不会**被中断/抢占。

**特点**：
- **进程自己让出 CPU** 的时机：**进程结束**、**发生 I/O（阻塞）**、等待事件。
- **不打断**正在运行的进程（即使有更高优先级的就绪进程）。
- **实现简单、开销小**（无需频繁保存/恢复），上下文切换少。
- **缺点**：响应时间**无保证**，**长进程/低优先级进程**可能长时间霸占 CPU，**实时性/交互性差**。
- 适合：**批处理系统**、**实时性要求不高**的场景。

**易错**：非抢占下，**优先级高的进程**不能抢占正在运行的低优先级进程，只能等它让出。响应时间不可控。

---

### 19. 抢占式调度的实现方式、特点

**核心**：**抢占式调度**下，**比当前进程优先级更高（或更紧迫）**的进程可以**强行打断**正在运行的进程，**抢走 CPU**。

**实现方式**：
- 需要**时钟中断**来**周期打断**运行进程（时间片到），或**事件/优先级变化**触发抢占。
- 高优先级进程**到达**时，立即暂停当前进程、**保存现场**，调度高优先级进程运行。
- 需**完善的中断/异常处理**与**上下文切换**机制。

**特点**：
- **响应快、实时性好**（保证紧急任务及时运行）、**公平**（时间片轮流）；
- 但**上下文切换频繁**，**开销大**，可能造成**低优先级进程饥饿**；
- 适合**分时系统、实时系统**。

**易错**：抢占是**从运行中被强行中断**（需保存/恢复现场），因此**开销比非抢占大**；**时间片轮转**本质是**抢占式**（时间片到即被抢）。

---

### 20. 何时不能进行进程调度

**核心**：**不能进行调度（进程切换）的时机**，通常是**原语/关键区/关中断/不可打断**的时刻。

**不能调度的情形**：
1. **关中断时**（中断被屏蔽，无法发生时钟中断或外部打断）。
2. **在中断处理过程中**（关键区，不能切换进程）。
3. **进程处于临界区/持有内核锁**时（避免破坏数据的原子性；虽然有些系统允许在临界区外抢占）。
4. **执行不可中断的系统调用/原语**（如某些原语期间）。
5. 进程切换本身**需要保存恢复现场**，是在**内核态**完成，**调度时机被触发**之后才切。

**可调度（发生调度）的时机**：进程**结束**、**阻塞（I/O/等待）**、**时间片到**、**被更高优先抢占**、自**愿放弃**等——即存在**让出 CPU 的机会**。

**记忆**：「关中断、中断处理中、临界区/持锁、原语执行中一般不可切换；常在进程让出/时间片到/阻塞/结束时调度」。

**易错**：**临界区**内通常**不允许**进程切换（否则破坏互斥/一致性）；**关中断**后既不能响应中断也不能切换。

---

### 21. 进程调度相关参数

**核心**：衡量调度算法好坏的参数（面向**周转时间**、**响应时间**、**利用率**）：

- **周转时间**：从**作业/进程提交到完成**的时间。`周转时间 = 完成时间 - 到达时间 = 运行时间 + 等待时间`。
- **带权周转时间**：`周转时间 / 运行时间`，反映等待相对运行的比例；值越小越好（理想为 1）。
- **响应时间**：从**提交到**首次**获得响应/结果**的时间（交互系统关注首响应）。
- **等待时间**：进程在就绪队列**等待（不被运行）**的总时间；`等待时间 = 周转时间 - 运行时间 - I/O 时间`。
- **CPU 利用率**：CPU 忙碌时间占总时间的比例。
- **吞吐量（吞吐率）**：单位时间内完成的作业/进程数。
- **平均周转时间、平均带权周转时间**：各进程周转时间/带权周转时间的**算术平均**，是调度算法的重要评价指标。

**记忆**：「周转=完成-到达；带权周转=周转/运行；响应=提交到首次响应；等待=周转-运行；CPU利用率=忙/总；吞吐=完成数/时间」。

**易错**：**响应时间**（首次获得响应）与**周转时间**（完成）不同；**带权周转时间**能反映短作业是否被优待（SRTF 追求带权周转小）。

### 22. 各种进程调度算法的概念、优缺点及作图法解决（含 PPT3P169 页问题）

> 参考图：《操作系统基础课件3-进程通信与进程调度》第 138、169 页。

**（1）先来先服务算法（FCFS）**
- **概念**：按**到达就绪队列的先后顺序**（FIFO）调度。
- **优点**：简单、公平、无饥饿。
- **缺点**：**对短作业不利**（长作业在前会拖慢），**带权周转时间差**，**响应时间**不可控。
- **适用**：结合时间片（如多级队列）或批处理。

**（2）优先级调度算法**
- **概念**：就绪队列中**优先级最高者**获得 CPU；分**抢占式**与**非抢占式**。
- **优点**：能体现重要程度/紧急性，实时性好。
- **缺点**：**低优先级饥饿**（长期得不到调度）、优先级若静态则不能适应变化。
- **解决饥饿**：**动态优先级（老化）**——等待越久优先级越高。

**（3）短进程优先调度算法（SPF/SJF）**
- **概念**：选择**预计运行时间最短**的进程优先运行（**SJF**，抢占式为之**最短剩余时间优先 SRTN**）。
- **优点**：**平均周转时间、平均带权周转时间最短**，对短作业/短进程有利。
- **缺点**：**长进程饥饿**、需要**预知运行时间**（不可靠）、交互性差。

**（4）最高响应比优先算法（HRRN）**
- **概念**：按**响应比**选择；`响应比 = (等待时间 + 运行时间) / 运行时间 = 1 + 等待时间/运行时间`。
- **优点**：**兼顾**短作业（运行时间短 → 响应比高）与等待久的作业（等待长 → 响应比高），**无饥饿**。
- **缺点**：**需要计算响应比**、仍是**非抢占**，且要预知运行时间。

**（5）时间片轮转法（RR）**
- **概念**：就绪进程按 **FIFO 排队**，每次分给一个**固定时间片**；**时间片到**则进程被强行**剥夺**，回到就绪队列**队尾**。
- **优点**：**响应快、公平、适合分时**、无饥饿。
- **缺点**：**上下文切换开销**随时间片变小而增大；时间片过大退化为 FCFS，过小则开销大。

**（6）多级队列调度算法**
- **概念**：按**类型/优先级**分成**多个独立队列**（如前台交互、后台批处理），各队列**适用不同算法**，且有**固定优先级**或**时间片分配**原则。
- **优点**：可**兼顾不同类型**任务；**缺点**：**低优先级队列可能饥饿**。

**（7）多级反馈队列调度算法**
- **概念**：多个**优先级由高到低**的队列；**新进进程**先入**最高优先级**队列，用**较小时间片**；**时间片用完**则降到**下一级队列**（时间片扩大）；顶级用 RR，末级用 RR/FCFS。
- **优点**：**兼顾响应时间（短作业/交互）与吞吐（长作业）**，**全智能、无饥饿**，是较通用的算法。
- **缺点**：实现**复杂**，参数（队列数、时间片）不易调。

**作图法（PPT3 P169 例题思路）**：画**甘特图（Gantt）**表示各进程在时间轴上的执行顺序；对每个进程标出**到达时间、运行时间、完成时间**；再计算**各进程周转时间、带权周转时间**及平均值。要点：**FCFS** 按到达序；**SJF/SPF** 每次选最短（可被新到更短抢占则按 SRTN）；**RR** 以时间片为单位轮转；**HRRN** 每时刻算响应比。

**记忆**：「FCFS 简单但偏短作业差；SJF 平均周转最短但要预知久、长饥饿；HRRN=1+等待/运行、无饥饿；RR 时间片轮转、响应快开销看时间片；多级队列分队列；多级反馈用优先级队列+逐级加大时间片、全面均衡」。

**易错**：**SJF 与 HRRN 都需要预知运行时间**（HRRN 是"非抢占 + 兼顾等待"）；**多级反馈**是**抢占式**、能解决饥饿；**多级队列**各队列独立算法、低优先级可能饥饿。

### 23. 多处理机调度的下列概念或方法

**（1）对称多处理机（SMP）与异构多处理机**
- **SMP**：多个**同构**处理器，**地位平等**，共享同一内存/总线，任何一个处理器都能运行任何进程；系统由**统一调度**管理。
- **异构多处理机**：处理器**性能/功能不同**（如有的专做 I/O、有的专做向量计算），按**适合的任务**分配，调度需考虑处理器能力匹配。

**（2）静态分配与动态分配**
- **静态分配**：进程创建后**固定**到某个处理器（或一组），**不迁移**。
- **动态分配**：进程在**运行时可在处理器间迁移**，负载均衡性好但切换开销大。

**（3）负载均衡**
- 使**多个处理器**的负载（运行/就绪任务数）**尽量均衡**，提高**整体利用率**。分**动态**（根据实时负载迁移任务）与**静态**。

**（4）处理器亲和性（Affinity）**
- 使某进程**尽量在同一处理器**上运行（通过**软/硬亲和**），提高**缓存命中率**（Cache 局部性好），减少迁移开销。

**（5）单队列调度与多队列调度**
- **单队列调度**：所有处理器**共用一个就绪队列**，谁闲谁取任务（动态负载均衡，简单但需同步，可能产生**队列竞争/迁移**）。
- **多队列调度**：每个处理器**自己一个就绪队列**（**处理器亲和性好、无竞争**，但可能负载不均，需要**负载均衡**）。

**（6）时间相关指标**
- **任务流时间（完成时间）**：任务从提交到完成的时间。
- **调度流时间**：即**周转时间**（提交到完成=等待+执行），反映任务完成快慢。
- **平均流时间**：各任务流时间的**平均**。
- **处理机利用率**：CPU 忙碌时间占总时间的比例。
- **加速比**：`单机时间 / 多机时间`（>1 表示并行加速，理想不超过处理机数）。
- **吞吐率（吞吐量）**：单位时间完成的任务数。

**记忆**：「SMP 平等共享；异构分工；静态不迁移/动态可迁移；负载均衡求均衡；亲和性求缓存命中；单队列共用一个队列（易均衡、有竞争），多队列各一个（亲和好、需均衡）；加速比=单机/多机时间」。

### 24. 实现临界区的软件方法：只利用 turn 和 flag 数组为什么不行？Peterson 算法为什么可以？

**核心**：进入临界区要满足**互斥、空闲让进、有限等待**。软件法用**共享变量**（turn、flag）实现；简单只用一个变量的方法**都有缺陷**（违反某条要求），**Peterson** 用**turn + flag 数组**的结合解决。

**（1）只利用 turn（单变量轮流等）**
```text
// 只有一个 turn 变量
while (turn != i);   // 轮到自己
// 进入临界区
turn = j;            // 让给对方
```
- **缺点**：**强制性轮流**，即使对方**不在临界区**、甚至**不在临界区附近**，自己也不能进入——**违反「空闲让进」**，造成不必要的互斥和低效（当一个进程离开后必须等对方先走）。

**（2）只利用 flag 数组（只声明意愿，无先后）**
```text
flag[i] = true;
while (flag[j]);   // 若对方也想去则等待
// 临界区
flag[i] = false;
```
- **缺点**：当**两个进程同时置 flag 为 true** 时，会**互相等待**对方——**违反「空闲让进」**，可能（在特定调度下）**死锁**（都等对方先让）。

**结论**：只用 turn 或只用 flag 都不行，因为它们**要么强制轮流**、要么**无法裁决并发竞争**，都不能同时满足**互斥 + 空闲让进 + 有限等待**。

**（3）Peterson 算法（turn + flag 结合）**
```text
flag[i] = true;
turn = j;                     // 先"礼貌地"把机会让给对方
while (flag[j] && turn == j); // 对方也想去且轮到他，则等
// 临界区
flag[i] = false;
```
- **为什么可以**：同时用了**两个变量**——**flag[i]** 表达"**我要进**"的**意愿**，**turn** 表达"**谁最后让出**"的**裁决**。
- **互斥**：关键时刻只有一个进程能通过 while 循环（turn 只有一值，两人中必有一人先出 while）。**空闲让进**：对方不参与时自己可进。**有限等待**：一旦对方在临界区，自己会被让出机会后进入（turn 保证轮流）。
- **特点**：满足**三要素**；但**仍会**忙等待（**违反三种经典要求中的'让权'**，仅软件、适合两进程）。

**记忆**：「turn 强制轮流（阻塞空闲进程）；flag 数组并发互等（可能都不进）；Peterson=flag 表达意愿+turn 做裁决，满足互斥/空闲让进/有限等待，但忙等待。只用一种变量必然失败」。

**易错**：这些都是**软件、忙等待（自旋）**方法；Peterson 只能解决**两进程**；**忙等待违反"让权等待"**（进程忙等而非阻塞），但满足互斥/空闲让进/有限等待。

### 25. 互斥锁：利用 swap 原语实现自旋锁和无忙等待锁

**核心**：**自旋锁（Spinlock）**基于**原子操作（swap/Test-and-Set）**实现，忙等待（自旋）抢锁；**无忙等待锁**（如信号量/互斥量阻塞版）在拿不到时让进程**阻塞（睡眠）**而不是空转。

**（1）利用 swap（Exchange）原语实现自旋锁**
`swap`（也称 exchange/XCHG）是**原子**地把寄存器的值和某地址（锁变量）的值**互换**。用 `lock=0` 表示空闲、`lock=1` 表示占用。
```text
// 进入临界区
key = 1;
again: swap(key, lock);
if (key == 1) goto again;   // 拿不到就重试（自旋）
// 临界区
lock = 0;                    // 释放
```
- key 初始为 1（永远置 1），swap 后若 lock 原来是 0（空闲），则 key=0、循环退出=拿到锁；若 lock 是 1（被占），则 key=1、继续自旋。
- **特点**：简单、**原子**，但**忙等待**（自旋浪费 CPU），适合**短暂持锁**（如多处理器、内核短临界区）。

**（2）无忙等待锁（阻塞式互斥量）**
- 用**信号量/互斥量**实现，**拿不到锁时调用 `block` 让进程阻塞**（进入等待队列、让出 CPU），**释放时唤醒**。
```text
mutex = 1;
P(mutex);   // 拿不到则阻塞（不让 CPU）
// 临界区
V(mutex);   // 释放并唤醒
```
- **特点**：**不忙等待**（睡眠让出 CPU，节省 CPU），但要**权衡**（块/唤醒系统调用开销较大），适合**长期持锁/用户态**。

**记忆**：「自旋锁靠 swap/Test-and-Set 原子操作、忙等、适合短临界区/多核；无忙等待锁=信号量/互斥量、拿不到就阻塞让 CPU、适合长持锁」。

**易错**：**swap 原语实现的是自旋锁**（忙等待）；**自旋锁不适合单 CPU 长时间持锁**（会浪费 CPU 且可能死等）；无忙等待锁通过**阻塞**而非自旋获得。

### 26. 信号量的实现方式：代码形式

**核心**：信号量是**同步原语**；其 `P`（wait/申请）与 `V`（signal/释放）必须是**原子操作**，且 P 在拿不到资源时**阻塞**（用**阻塞队列**实现，而非忙等）。

**数据结构**：`semaphore` = 一个**整型值 S** + 一个**等待队列（list）** + **一个锁（保证 S 操作的原子性）**。

**代码实现（PV 原语）**：
```text
// 信号量类型
struct semaphore { int value; list<process> queue; };
// wait 原语（P）
void P(semaphore &s) {
    s.value = s.value - 1;
    if (s.value < 0) {
        // 将当前进程加入 s.queue（阻塞），
        // 并让出 CPU（block 原语）。
        block(s.queue);
    }
}
// signal 原语（V）
void V(semaphore &s) {
    s.value = s.value + 1;
    if (s.value <= 0) {
        // 从 s.queue 摘下一个进程唤醒（wakeup），
        // 挂到就绪队列。
        wakeup(s.queue);
    }
}
```
**要点**：
- **P**：先自减；若 **value < 0** 则当前进程**阻塞**（入等待队列、让出 CPU）。value 为 0 及以上表示可申请成功。
- **V**：先自增；若 **value ≤ 0** 说明有进程在等，**唤醒**其中一个。
- value 的**语义**：初值表示可用资源数；**value 为负数时**其**绝对值** = **等待的进程数**。
- **原子性**：对 s.value 的**检查与修改**必须在**原语/关中断**或**互斥锁**保护下（不可分割）。
- **计数信号量 vs 二值信号量**：value 初值 >1 为计数；初值 =1 为**二值信号量（互斥锁）**。

**记忆**：「P=value-1，若<0 则阻塞入队；V=value+1，若<=0 则唤醒出队；value<0 绝对值=等待进程数；检查与修改需原子（关中断或锁）」。

**易错**：P 在**拿不到时阻塞**（不是忙等）；V 唤醒是**把进程移到就绪队列**并不直接运行；**PV 修改必须原子**（否则竞态）。

### 27. 信号量解决同步互斥问题的一般步骤

**核心**：信号量解决两类关系——**互斥**（多个进程争抢同一资源）与**同步**（进程执行有一定的先后顺序/协作）。

**一般步骤**：
1. **区分关系**：判断是**同步**（有序、协作、信号量充当"事件/许可"）还是**互斥**（独占资源、信号量初值 1 充当锁）。
2. **设置信号量**：
   - **互斥**：设 **互斥信号量 mutex = 1**，临界区前后 `P(mutex)`、`V(mutex)`（**同一进程 P 和 V 配对**）。
   - **同步**：设 **同步信号量 s**，初值按**可用信号**设（0 或 N）；在**等待方**前 `P(s)`，在**产生方**后 `V(s)`（**不同进程的 P-V 配对**）。
3. **每个进程写**：申请（P）→ 使用 → 释放（V）。
4. **检查**：**互斥的 P/V 必须成对在同一进程内**；**同步的 P/V 成对在不同进程（生产者/消费者）**；避免**死锁**（注意 P 的顺序、信号量初始值）。
5. **万能套路**：先考虑**同步**（先后关系 → 信号量），再考虑**互斥**（临界区 → mutex）。

**记忆**：「先定关系（同步/互斥）→ 设信号量（互斥初值1、同步按序设初值）→ 每个进程 P→处理→V → 检查成对与死锁；同步的信号量在"事件到达"处 V、"等待事件"处 P」。

**易错**：**互斥信号量**的 P/V 在**同一个进程**内成对（自己锁自己，防别人）；**同步信号量**的 P/V 在**不同进程**（一方发 V 通知，另一方 P 等待）。**P 的顺序不当会导致死锁**（如两个进程都先 P 再 P 不同号死锁）。

### 28. 用公式方法解决生产者消费者问题

**核心**：**生产者-消费者**问题是一个**同步（资源缓冲） + 互斥（访问共享缓冲）**的组合。**公式（约定）法**：给每个**同步关系**设一个**信号量**，给**共享资源**设一个**互斥信号量**。

**信号量设置（公式）**：
- `mutex = 1`：**互斥**访问缓冲池（保证同一时刻只有一个进程操作缓冲区）。
- `empty = N`（N 为满缓冲容量）：**空闲缓冲区数量**，生产者**每放一个 P(empty)**，消费者**每取一个 V(empty)**。
- `full = 0`：**已满缓冲区数量**，消费者**每取一个 P(full)**，生产者**每放一个 V(full)**。

**代码（生产者/消费者，循环缓冲）**：
```text
// 生产者
while (1) {
  produce an item;        // 生产
  P(empty);               // 申请一个空缓冲
  P(mutex);               // 进入缓冲互斥
  put item into buffer;
  V(mutex);               // 退出缓冲
  V(full);                // 通知有数据
}
// 消费者
while (1) {
  P(full);                // 申请一个满缓冲
  P(mutex);
  take item from buffer;
  V(mutex);
  V(empty);               // 释放空缓冲
  consume item;           // 消费
}
```

**关键点（公式/顺序）**：
- **互斥 P(mutex) 放在同步 P 之后**（先 P(empty/full) 再 P(mutex)；若先 P(mutex) 会因等 empty 时占住 mutex 导致其它进程也拿不到 → 死锁）。
- **V 的顺序可互换**（先 V(mutex) 再 V(full/empty)），不会死锁。
- **缓冲池容量 N**；满时生产者 P(empty) 阻塞，空时消费者 P(full) 阻塞。

**记忆**：「mutex=1 防互斥、empty=N 防满、full=0 防空；先 P 同步(empty/full) 再 P 互斥(mutex)；V 任意顺序。P(empty)P(mutex) 不能颠倒，否则死锁」。

**易错**：**P(empty) 必须放在 P(mutex) 之前**（否则满缓冲时生产者占 mutex 等 empty → 消费者又等 mutex → 死锁）；**V 顺序无关**；单缓冲/多生产者多消费者同理，只需加各自的 P/V。

### 29. 读者、写者问题的解决方法

**核心**：**读者-写者**允许**多个读者同时读**，但**写者独占**（写与任何进程互斥）。核心策略：**读优先**或**写者优先**，用**计数器 + 互斥信号量**表达"是否有读者在"。

**读者-写者（读优先/读者优先）**：
- 信号量：`rw_mutex = 1`（写者与读写互斥）、`mutex = 1`（保护读者计数 readcount）、`readcount = 0`。
- **读者**：
```text
P(mutex);
readcount = readcount + 1;
if (readcount == 1) P(rw_mutex);   // 第一个读者锁住"写者进入"
V(mutex);
// 读操作
P(mutex);
readcount = readcount - 1;
if (readcount == 0) V(rw_mutex);   // 最后一个读者释放"写者进入"
V(mutex);
```
- **写者**：
```text
P(rw_mutex);
// 写操作
V(rw_mutex);
```
- **特点**：只要**有读者在读**（readcount>0），写者就**被阻塞**；新读者可**不断加入**（读者优先），写者可能**饥饿**。

**写者优先（写者优先）**：加一个**写者等待计数器**或**信号量标记"有写者等待"**，使**新读者**在写者等待时**不进入**（或排队），让写者优先。

**记忆**：「rw_mutex 管读写互斥；mutex 管 readcount 互斥；第一个读者 P(rw_mutex)、最后一个读者 V(rw_mutex)；写者直接 P/V(rw_mutex)。读优先=写者可能饥饿（count>0 写不下）；写者优先=后到读者被拦」。

**易错**：**readcount 的修改要互斥**（用 mutex 保护）；**第一个读者**才申请读锁（P(rw_mutex)），**最后一个**才释放；写者用同一把 rw_mutex 与"读的群体"互斥。**读者优先会让写者饥饿**，写者优先会降低并发。

### 30. 信号量和辅助变量的区别

**核心**：**信号量**是**带阻塞队列**的同步原语，能**让进程睡眠**；**辅助变量（普通共享变量/计数器）**只是**普通变量**，本身**不提供原子操作和阻塞**。

**区别**：
- **信号量**：有 **value + 等待队列**；P/V 是**原子**的，P 拿不到就**阻塞**、V 唤醒，**能实现同步与互斥**、**让权等待**。
- **辅助变量**（如 count、readcount、标志位 flag）：**只能保存一个值**，对它的**检查与修改不是原子**的，**不会阻塞**进程，**不能单独实现同步互斥**，须配合**信号量/锁**使用（例如用 mutex 保护 readcount）。
- **作用**：信号量**承担同步/互斥职责**；辅助变量**表达状态**（如当前有几个读者、是否空闲），但应放在**临界区/加锁**下修改，避免竞态。

**记忆**：「信号量=原子原语+能阻塞（睡眠）、专管同步互斥；辅助变量=普通共享变量、只表达状态、本身不原子不阻塞、要加锁保护」。

**易错**：**计数器（辅助变量）必须被互斥保护**，否则并发读写会竞态；**不能把辅助变量当信号量用**（没有阻塞队列、无原子性）。

### 31. PPT4 理发师问题

> 参考图：《操作系统基础PPT4-同步互斥与死锁》第 100、107 页。

**问题**：一个理发师、一把理发椅（1 个理发位）、n 把候等椅（等待容量 n）。若没人理发师就睡；来了顾客若有空椅子就坐（并叫醒理发师），没空椅子就走；理发师有空就理，理完看是否还有顾客。

**信号量设计**：
- `chairs = n`（**剩余可坐的等待椅**，计数信号量，初值 n）。
- `customers = 0`（**等待理发的顾客数**，即"有没有顾客"，初值 0）。
- `barbers = 0`（**空闲的理发师数**，初值 0，顾客等理发师）。
- `mutex = 1`（**互斥**保护 chairs / 座位数 的修改）。

**顾客进程**：
```text
P(mutex);
if (chairs > 0) {           // 有座位
  chairs = chairs - 1;      // 占一个座位
  V(mutex);
  V(customers);             // 通知理发师"有顾客"
  P(barbers);               // 等理发师空闲
  // 坐在理发椅上理发
  P(mutex);                 // 理完可能释放（简化）
  ...
} else {                    // 无座位
  V(mutex);
  // 离开（可选择）
}
```
**理发师进程**：
```text
while(1) {
  P(customers);             // 等顾客（若 customers=0 则睡）
  P(mutex);
  chairs = chairs + 1;      // 顾客离开椅子去理发（释放座位）
  V(mutex);
  V(barbers);               // 叫顾客可到理发椅
  // 理发
}
```
**关键**：`customers` 用于**理发师休眠/被唤醒**（顾客来了 V(customers) 唤醒理发师）；`barbers` 让顾客**等理发师**；`chairs+mutex` 控制**座位数**（空闲走人）。

**易错**：区分三个信号量的职责——**chairs 管座位**、**customers 管"有无顾客"（叫醒理发师）**、**barbers 管"理发师空闲"**（顾客等理发师）。**若没有空剪位置**，顾客在座位满时**离开**（而非阻塞）。

### 32. 条件变量实现

**核心**：**条件变量（condition variable）**配合**互斥锁（mutex）**使用，用于**在某个条件不满足时让线程等待**，条件满足时**唤醒**。

**数据结构与操作**：
- `condition` 带一个**等待队列**；**必须与一个互斥锁关联**。
- **`wait(cond, mutex)`**：**原子地**（1）**释放 mutex**、把当前线程加入 **cond 的等待队列**、让线程**睡眠（阻塞）**。当被唤醒再从队列移出并**重新获得 mutex**。
- **`signal(cond)`**：唤醒**一个**等待在 cond 上的线程（若无则不做）。
- **`broadcast(cond)`**：唤醒**全部**等待线程。

**关键**：
- 使用模式：**`lock(mutex)` → `while (条件不满足) { wait(cond, mutex); }` → 使用 → `unlock(mutex)`**。
- **while 而非 if**：被唤醒后条件可能又不成立（**虚假唤醒**），所以用 while 重判。
- 条件变量与信号量区别：条件变量**不记录"事件是否已发生"**（无计数器），信号量有 value（计数）；条件变量**必须配合锁**且**没有"唤醒次数"缓存**，丢失唤醒信息。

**记忆**：「条件变量=等待条件、配锁；wait 原子释放锁+睡眠，signal/broadcast 唤醒；用 while 重判防虚假唤醒；条件变量无计数器（与信号量不同）」。

**易错**：**wait 必须释放锁**（否则其它线程拿不到锁，条件无法改变→死锁）；**signal 唤醒后线程要重新加锁**；**用 while 而非 if 重判**。

### 33. 用管程和条件变量解决生产者、消费者问题

**核心**：**管程（Monitor）**将**共享数据**与**对它的操作**封装在一起，保证**同一时刻只有一个进程进入管程**（互斥由管程自动保证）；用**条件变量**（x.wait / x.signal）表达同步。

**管程结构**：
```text
monitor BoundBuffer {
  item buffer[N]; int in=0, out=0, count=0;
  condition notFull, notEmpty;   // 满/空两个条件变量

  entry void put(item x) {
    while (count == N) notFull.wait();   // 满则等
    buffer[in] = x; in = (in+1)%N; count = count+1;
    notEmpty.signal();                    // 通知有数据
  }
  entry item get() {
    while (count == 0) notEmpty.wait();   // 空则等
    item x = buffer[out]; out = (out+1)%N; count = count-1;
    notFull.signal();                     // 通知有空位
    return x;
  }
}
```
- **互斥**：管程保证**同时只有一个进程**在管程内（put/get 互斥）。
- **同步**：生产者满时 `notFull.wait()`（释放管程，等消费者取走后再进）；消费者空时 `notEmpty.wait()`；双方 `signal` 唤醒。
- **signal 语义**：`notFull.signal()` 唤醒一个等待在 notFull 上的进程（Hoare 或 Mesa 语义；Mesa 下被唤醒者重新竞争进入管程）。

**对比信号量方案**：管程**把互斥内置**（不用手写 mutex 与 P/V 顺序），用**两个条件变量**表达"满/空"两个条件，**更不易出错**，但需支持（如 Java synchronized、pthread 条件变量）。

**记忆**：「管程=数据+操作封装、自动互斥；notFull/notEmpty 两个条件变量表达满/空；满则 wait、取走则 signal；while 重判防虚假唤醒」。

**易错**：管程的**互斥是自动**的（不需要额外 mutex）；条件变量 wait 会**释放管程**；**用 while 而非 if**。

### 34. 死锁的 4 个必要条件

**核心**：死锁是**多个进程**互相等待对方占有的资源，导致**都不能推进**。其产生需**同时满足**四个必要条件：

1. **互斥条件**：资源**一次只能被一个进程**使用（非共享）。
2. **不剥夺条件**：进程已获得的资源只能由它**自己主动释放**，**不能**被其它进程/系统**强行剥夺**。
3. **请求并保持条件**：进程**已经占有一个资源**，又**再次申请新的资源**，且**不释放**已有资源。
4. **循环等待条件**：存在一个**资源-进程**的**环路**（进程 A 等 B 的资源、B 等 C、C 等 A 等），形成**循环等待**。

**记忆**：「互斥、不剥夺、请求保持、循环等待」四条件**必须同时成立**才可能死锁；**破任意一个**即可预防死锁。

**易错**：这四个是**必要条件**，不是充分条件（四个都满足也不一定死锁，但死锁必然四个都成立）。**循环等待**是死锁的重要标志（由资源分配图判断）。

### 35. 处理死锁的不同方法？分别是什么含义？

**核心**：处理死锁有三大类策略：**预防、避免、检测与解除**；外加**忽略（鸵鸟算法）**。

**（1）死锁预防（Prevention）**
- 通过**破坏 4 个必要条件之一**，使死锁**不可能发生**。
- 破坏**互斥**（可共享资源不去除，仅对不可共享资源）；破坏**不剥夺**（申请新资源时释放已有的，或可被剥夺）；破坏**请求并保持**（一次性申请**全部**资源；申请不满足就不占）；破坏**循环等待**（给资源**编号**，按**递增顺序**申请）。
- **优点**：简单、静态；**缺点**：资源利用率**低**（一次申请全部/破坏性释放）。

**（2）死锁避免（Avoidance）**
- 在**每次分配资源前**判断是否会导致**不安全状态**，保证系统**始终处于安全状态**，从而**避免死锁**。
- 典型**银行家算法**；需要**事先知道**每个进程的**最大需求**和**当前已分配/可用**。
- **优点**：利用率较高；**缺点**：需预知最大需求（难以获得）、开销大。

**（3）死锁检测与解除（Detection & Recovery）**
- 允许死锁发生，用**检测算法**（如资源分配图 + 安全状态判断/死锁定理）**发现**死锁，再**解除**：**剥夺资源、终止进程（一次性终止部分/全部）、回退**等。
- **优点**：利用率高；**缺点**：需检测开销、解除会中断/损失。

**（4）忽略（鸵鸟算法）**
- 不处理（认为死锁罕见），由用户重启；如 UNIX 等，简单、开销小，但可能浪费。

**记忆**：「预防=破4条件之一（静态、利用率低）；避免=分配前判安全（银行家）；检测解除=允许发生再发现再处理（剥夺/终止/回退）；忽略=不处理（鸵鸟）」。

**易错**：**预防**是"**杜绝发生**"（破坏必要条件）；**避免**是"**分配时避开不安全状态**"（动态判断）；**检测解除**是"**事后处理**"。三者**事前/事中/事后**思路不同。

### 36. 死锁避免算法及银行家算法全过程

> 参考图：《操作系统基础PPT4-同步互斥与死锁》第 157 页（安全状态与死锁关系）。

**核心**：**银行家算法**是一种**死锁避免算法**。系统在**分配资源前**，判断分配后系统是否仍**安全**；若安全才分配，否则**阻塞/拒绝**。

**相关数据结构**：
- **Available[m]**：当前**可用**资源向量。
- **Max[n][m]**：每个进程的最大需求矩阵。
- **Allocation[n][m]**：当前已**分配**给每个进程的资源。
- **Need[n][m] = Max - Allocation**：每个进程**还需**的资源。

**（1）资源申请（Request[i]）算法**：某进程 Pi 申请资源向量 Request：
1. 若 `Request[i] ≤ Need[i]`，否则报错（超过最大需求）。
2. 若 `Request[i] ≤ Available`，否则**进程等待**。
3. **试探性分配**：`Available -= Request`；`Allocation[i] += Request`；`Need[i] -= Request`。
4. 调**安全性算法**判断此时系统是否**安全**：
   - **安全** → 真实分配；**不安全** → **撤销试探**、进程**等待**。

**（2）安全性算法**：找**安全序列**：
1. `work = Available`；`finish=false`（全部进程）。
2. 找一个**满足 `Need[i] ≤ work` 且 `finish[i]=false`** 的进程 i。
3. 若找到：`work += Allocation[i]`；`finish[i]=true`；回步骤 2。
4. 若**所有 finish=true** → 系统**安全**；否则**不安全**。

**记忆**：「申请：Request≤Need、≤Work 才试分；试分后跑安全性（找 finish 序列）；安全生产序列=依次满足 Need≤work、work+Allocation；找到即安全、否则不安全则回退」。

**易错**：**安全状态必无死锁，不安全状态可能死锁**；**银行家算法是避免**（非预防），**需要预知各进程最大需求**（Max）。满足**Need≤Work** 才能推进，安全序列**不一定唯一**。

### 37. 哲学家就餐问题

**核心**：5 个哲学家围圆桌，每位哲学家用左右**两把叉子**才能吃；**每个叉子同一时刻只能被一人用**。问题本质是**多个进程争用多个互斥资源**，处理不好会**死锁**（每人拿一把，环等）或**饥饿**。

**资源建模**：5 把叉子 = 5 个二值信号量 `chopstick[5] = {1,1,1,1,1}`。

**（1）初级（易死锁）方案**：
```text
P(chopstick[i]);      // 拿左边
P(chopstick[(i+1)%5]);// 拿右边
// 吃饭
V(chopstick[(i+1)%5]);
V(chopstick[i]);
```
**缺陷**：若**5 人同时拿左边叉子**，则形成**循环等待 → 死锁**。

**（2）解决死锁/饥饿的方法**：
- **方案 A：最多允许 4 个哲学家同时拿叉**（用信号量 `room=4`，进前 P(room)、吃完 V(room)）。
- **方案 B：破坏循环等待**——给叉子**编号**，哲学家**先拿小号**再拿大号（偶数先左后右、奇数先右后左等，或按固定升序）。
- **方案 C：奇数号先拿左/右、偶数号先拿右/左（错开，避免同时拿同一方向的叉）**。
- **方案 D：同时拿起两把**（用互斥锁保护的**原子"检查+拿两把"**，保证要么都拿要么都等）。

**记忆**：「每个哲学家=两个互斥叉子（两个 P）→ 处理不当会循环等死锁；解法：限人数≤4、按号序拿、奇偶错开、要么同时拿两把」。

**易错**：哲学家就餐的**死锁**来自**每个哲学家先拿一支叉子**形成环形等待；**破坏循环等待**或**限制同时拿的人数**都能避免。

### 38. 死锁检测算法

**核心**：**死锁检测**允许死锁发生，通过**资源分配图/安全性判断**发现**是否存在死锁**，以便**解除**。常用**资源分配图化简法**或**与银行家算法类似的需求≤work 法**。

**（1）资源分配图（RAG）化简法**
- 图：**进程圆节点**、**资源方节点**；**申请边**（进程→资源，表示请求）、**分配边**（资源→进程，表示已分配）。
- **化简规则**：若某进程 P 的**所有申请都能被满足**（对应资源均有可用），则可**认定可完成 → 删除它相关的所有边**，把它释放的资源还回。反复化简。
- **死锁判定**：若化简后**仍有环/仍有进程不能化简**（剩余申请边），则**存在死锁**；否则不死锁。

**（2）用"请求≤可用"法（类似安全性）**
- `work = Available`；`finish=false` 初始。
- 循环找满足 `Request[i] ≤ work` 且 `finish[i]=false` 的进程，`work += Allocation[i]`，`finish[i]=true`。
- **死锁检测**：若循环后**仍有进程 finish=false**（其请求无法满足，形成环路），则**存在死锁**；被卡住的就是**死锁进程**。
- 与**避免**的区别：**避免**用 **Need（最大需求）** 判断"未来安全"；**检测**用 **Request（当前请求）** 判断"现在是否卡住"（**死锁定理**）。

**记忆**：「检测用 Request<=work 判卡住（非 Max）；资源分配图化简——能化简的都删，剩余有环=死锁；死锁进程=化简后仍不能完成的进程」。

**易错**：检测（用**Request**，事中/事后）与避免（用**Max=Need**，事前）**用的量不同**；检测到死锁后用**剥夺/终止/回退**解除。

## 第三章 内存管理

### 1. 内存管理解决的问题

**核心**：内存管理负责**内存的分配、回收、保护和地址转换**，要解决的主要问题：

- **分配与回收**：为进程**分配内存**，进程结束**回收**，管理空闲块。
- **地址转换（地址映射）**：把程序中的**逻辑/虚地址**转换为**物理地址**（由装入、重定位、MMU 完成）。
- **内存保护**：防止进程**越界访问/越权访问**（访问不属于自己的区域），保证**隔离**。
- **内存扩充/虚拟内存**：在有限物理内存下，通过**虚拟存储（换入换出）**让程序**能运行超过物理内存大小**的逻辑空间（扩充内存）。
- **提高利用率、减少碎片**：提升内存利用率，减少内部/外部碎片。

**记忆**：「内存管理四件事：分配回收、地址转换、内存保护、内存扩充（虚拟内存）+ 减少碎片」。

**易错**：内存管理**不只是分配**，还包括**地址转换、保护、虚拟化（扩充）**。**内部碎片**（分配给进程但未用的）与**外部碎片**（内存中不可用的小空闲块）往往权衡。

---

### 2. 绝对装入、静态重定位、动态重定位的含义、实现方式和过程

**核心**：这三种是**装入（地址绑定）**的不同方式，处理**逻辑地址→物理地址**的时机不同。

**（1）绝对装入**
- **含义**：链接/编译时就**确定**程序的**物理地址**（用户提供或编译时指定物理地址），程序必须装入**固定的物理地址**运行。
- **实现**：编译/装入时按**绝对地址**；地址在**编译时**已绑定。
- **特点**：**简单但极不灵活**，只适合**单道/固定**、已知地址的环境（如操作系统内核、早期单一内存块）；**地址改变需重编译**。

**（2）静态重定位（可重定位装入）**
- **含义**：把程序装入内存时，由**装入程序**一次性把逻辑地址**加上**基址（装入的起始物理地址），在**装入时**完成重定位；此后**不再改变**。
- **实现**：装入程序对每条**指令/数据地址**进行**重定位**（加基址），生成可执行代码。
- **特点**：**不改变物理地址**（运行中不活动），需**连续**内存；**程序运行期间不能再移动**。**无法**在运行被换出又换入。

**（3）动态重定位（运行时装入）**
- **含义**：**装入时不重定位**，把逻辑地址**原样**装入；**运行时**由**MMU（动态重定位寄存器/基址寄存器）**把每次访问的逻辑地址**叠加基址**得到物理地址。
- **实现**：用**重定位寄存器（基址寄存器）**，CPU 访存时保证「物理地址 = 基址 + 逻辑地址（在运行期，每条指令生成时计算）」。
- **特点**：**灵活**，程序可**装入任意位置、运行中可移动**（配合换入换出/紧凑）；是**页式/段式/虚存**的基础。需要**额外硬件（MMU）**和有**地址越界检查**。

**记忆**：「绝对=编译时定死物理地址；静态=装入时重定位（装入后不移动）；动态=运行时靠基址寄存器每次转换（可移动/换入换出，虚存基础）」。

**易错**：**静态重定位在"装入时"完成、运行中不能移动**；**动态重定位在"每条指令执行时"完成、可移动**；动态重定位是**现代内存/虚存**的基础，需**硬件 MMU/重定位寄存器**。

---

### 3. 装载时动态链接和运行时动态链接的实现方式

**核心**：动态链接指把链接推迟到**运行期**；分**装载时动态链接**与**运行（执行）时动态链接**。

**（1）装载时动态链接**
- **含义**：程序**装载到内存时**才链接所需库（目标模块），把库代码装入内存并**重定位**；未用到的模块不装入。
- **特点**：**只在装入时链一次**；比静态省内存（只装入用到的库），但**比运行时链接早**（启动仍要链）。修改库需**重新装载**。

**（2）运行时动态链接**
- **含义**：**运行时**（程序执行中）**才调入/链接**需要的共享库（如 `dlopen`）；只有**用到某模块时才链接**它。
- **特点**：**省内存、省时间**（不用的模块、库不装入）；库**可共享**（多进程共用**同一份库**）；**灵活、可热更新**；但**运行时开销**、需**符号解析**（延迟绑定/COW）。
- **共享库/动态链接库（DLL/.so）**：供多个进程共享，**一个物理加载、映射到多个进程地址空间**。

**记忆**：「装载时动态链接=装入时链库（一次）；运行（执行）时动态链接=用到才链（dlopen）、省内存、可共享、灵活但运行时有开销」。

**易错**：**动态链接**解决的是**内存与灵活性**问题（库共享、用到才链）；与**静态链接**（链死的库、结果大、可移植差）不同。运行时动态链接**用到才加载**，还能减少**启动时间**。

### 4. 地址越界和地址越权的区别

**核心**：这是两种**内存保护**的判定，都可能导致进程被终止/触发异常：

- **地址越界（越界访问）**：进程访问的**逻辑地址超出了**它**本应拥有的地址空间范围**（如访问一个超过其合法地址上限的地址）。检查方法：**界地址寄存器 / 上下界比较**。越界 = **地址本身不合法**（超出允许范围）。
- **地址越权（越权访问/访问违规）**：进程访问了**地址空间范围内**的地址，但**权限不符**（如只读区写入、用户态访问内核区、无权访问的段）。检查方法：**访问权限位/存取控制**。越权 = **地址合法但操作权限不合法**（读/写/执行权限不匹配）。

**区别**：
- 越界针对**"地址值是否落在合法区"**（范围问题）；越权针对**"对合法地址的操作权限"**（权限问题）。
- 例如：一个段只读，进程写入该段是**越权**（地址在范围内）；进程访问一个**不存在/超范围**的地址是**越界**。

**记忆**：「越界=地址值超范围（界寄存器判定）；越权=地址合法但读写权限不符（权限位判定）。都触发异常/缺页」。

**易错**：**越界**是**范围**问题、**越权**是**权限**问题；分段/分页下**地址合法性**（越界）与**存取权限**（越权）是**两套检查**。

---

### 5. 地址检查：上下界寄存器、界地址寄存器

**核心**：用于**内存保护**的**地址检查**方法，主要用在**连续分配/分段**下：

**（1）上下界寄存器（基址/界址）**
- 用**两个寄存器**——**基址寄存器（BR，下界）**和**限长寄存器（LR，上界/界地址）**，记录进程内存区间的**起始地址**和**长度**。
- 检查：CPU 计算物理地址后，判断 **基址 ≤ 物理地址 < 基址 + 长度**；若不满足则**越界**，产生**保护性异常/地址越界中断**。

**（2）界地址寄存器（单界址）**
- 只用**一个界址寄存器**记录**上限**，配合**基址**；或记录**限长**（范围）用于越界判定。
- 有时与**重定位寄存器**合一：`物理地址 = 基址 + 逻辑地址`，并检查 `逻辑地址 < 限长`（越界）。

**作用**：**防止进程访问其它进程或系统区域**，实现**内存保护**。多用于**连续分配/静态/动态分区**；在**分页/分段**下退化为基础（页表项含**有效位/权限位**，越界由**页号是否超过页表长度**判断）。

**记忆**：「上下界寄存器=基址+限长，判定"基址≤物理地址<基址+限长"；界址寄存器（限长寄存器）=记录范围上限；用于连续/分区分配的越界检查；分页改用页表项+有效位」。

**易错**：**基址寄存器**常与**重定位寄存器**结合（动态重定位用基址+限长），**同时完成转换与越界检查**；检查的是**逻辑地址**是否超限（`逻辑地址 < 限长`）或**物理地址**是否在区间内。

### 6. 连续内存分配中的单一连续分配、固定分区分配、动态分区分配的概念

**（1）单一连续分配**
- **含义**：内存**只分两区**：**系统区**（OS 占用）与**用户区**（只能放一道用户程序）。
- **特点**：**简单、无碎片**（用户区整体一块），但**只支持单道**，内存利用率低、不支持多道。

**（2）固定分区分配**
- **含义**：把用户区**预先分成若干个固定大小**的分区（可相等也可不等），每个分区**只能装一道**程序。
- **特点**：支持**多道**，实现简单；但**分区大小固定**造成**内部碎片**（程序小于分区则浪费），且**不适应不同大小作业**（利用率低）。
- 需要**分区分配表**记录使用状态。

**（3）动态分区分配**
- **含义**：**不预先分区**，根据**作业/进程实际需要**在**装入时**动态**划分**一块大小合适的连续内存区。
- **特点**：**灵活、无内部碎片**（按需分配），但会产生**外部碎片**（释放后留下很多小空闲块），常需**紧凑（压缩）**处理；要求**连续的物理内存**，实现比固定分区复杂。

**记忆**：「单一连续=只支持单道（系统+用户两区）；固定分区=预先固定若干分区（有内部碎片）；动态分区=按需划分连续区（无内部碎片、有外部碎片、需紧凑）」。

**易错**：**固定分区**有**内部碎片**；**动态分区**有**外部碎片**（需要紧凑）。这是**连续分配**的碎片差异。

---

### 7. 动态分区分配相关知识：实现、选择可用空闲内存块的方法及各自特点

**（1）实现**
- 用**空闲分区表**（记录每块空闲区：地址、大小）或**空闲分区链**（链表）来**登记**空闲块。
- 分配时在**空闲表/链**中找一个**满足大小**的空闲区，**划分**给进程；释放时把回收块**并入**空闲表（合并相邻空闲块）。

**（2）选择可用空闲内存块的方法（放置策略）及特点**
- **首次适应（First Fit）**：按地址**递增顺序**，**第一个**满足大小的空闲区分配。
  - 特点：**简单、查找快、保留大的空闲区**（把小的用完），回收时易靠近低地址；**易产生外部碎片**（留下的碎片集中在前部）。
- **最佳适应（Best Fit）**：选择**能满足且剩余最小**的空闲区（找**最接近需求**的块）。
  - 特点：**留下更小碎片、更利于大作业**；但会**产生大量难以利用的小碎片**，**分割后留给后边很碎**；查找**成本高**（需遍历或排序）。
- **最坏适应（Worst Fit）**：选择**最大**的空闲区。
  - 特点：**剩余块仍较大**，可被后续使用；但**大块被切碎**，可能**浪费大块**；查找需排序/遍历。
- **邻近适应（Next Fit，下次适应/循环首次适应）**：从**上次查找位置**继续向后找（循环）。
  - 特点：查找更**快**（不从头），但**破坏了大块的整体利用**、可能**留下较多外部碎片**（低地址空闲难利用）。

**记忆**：「首次适应=从小到大找第一个（快、存大块）；最佳=找最贴合的（剩小碎片多、利大作业）；最坏=找最大块（切碎大块）；邻近=循环+接着上次找（快但碎片集中）」。

**易错**：**最佳适应**并不是**最优**——它产生很多**小碎片**（外部碎片）反而**难再利用**；**首次适应**常是**综合较好**的；放置策略是**动态分区分配**的核心。

---

### 8. 基于索引的动态内存分配算法：快速适应算法和哈希算法的概念

**核心**：这些是**结合查找结构（索引/哈希）**来加速「找空闲块」的**动态分区**算法。

**（1）快速适应算法（快速分配）**
- **概念**：预先按**空闲块的大小**建立**多个空闲链**（把空闲块按大小**分档**，每档一个链表，如 8K、16K、24K…），并为每种大小建立一个**索引/表**。
- **分配**：按需求大小查对应**大小档的链表**，直接取一块（无需遍历所有块）。**回收**：放回对应链条。
- **特点**：**分配快**（按大小索引定位）；但**分割时**可能产生**碎片**、管理**比较复杂**、大的空闲区可能被切成小块难再用（内存利用率不一定高）。

**（2）哈希算法**
- **概念**：用**哈希（散列）函数**把**空闲块大小**映射到**哈希表**中的位置；每个哈希桶（槽）存放**对应大小的空闲块链表**。
- **分配**：按需求大小求哈希，定位到对应槽，取空闲块。
- **特点**：**查找接近 O(1)**，比遍历快；但**哈希冲突**需要处理（如链地址法），且按哈希值分桶后可能仍面临**碎片**与**桶内分配**管理。

**记忆**：「快速适应=按大小分档建立多个空闲链+索引表（按大小直接取快但可能碎片、复杂）；哈希=用哈希函数把大小映射到哈希表（O(1) 查找，处理冲突）」。

**易错**：**快速适应**与**哈希**都是**索引/查找优化**（加速空闲块查找），不是解决碎片；它们都以**预先划分大小档**为代价，管理更复杂，可能**牺牲高地址大块**。

---

### 9. 伙伴算法的设计

**核心**：**伙伴算法（Buddy System）**是**把内存按 2 的幂次分组**的一种分配方式，能**高效分配与合并**，减少外部碎片。

**设计**：
- 内存按**2 的幂**大小划分块（如 2^k）；为**每种大小（2^k）**维护一个**空闲块链表**（含**伙伴**关系）。
- **分配**：从满足的最小 2^k 链找；若该层**无空闲**，向**上一层（2^(k+1)）**请求并**对半分**（分裂成两个伙伴，一个用于分配，一个挂到下层链）。递到有为止。
- **释放与合并（伙伴合并）**：释放 2^k 块时，若它的**伙伴（相邻且同大小的 2^k 块）也空闲**，则把两者**合并**成 2^(k+1) 块，再继续向上检查合并，直到无法合并。
- **伙伴定义**：两块**大小相同、地址相邻**且**起始地址相差一个 2^k** 的块互为伙伴（可由地址的**第 k 位**判断）。

**特点**：
- 快（O(1) 级分裂/合并操作）；**合并简单**（伙伴空闲即合并），**碎片较少**；
- 但**内部碎片**（分配不恰好是 2 的幂时浪费）；**只适合 2 的幂分配**（非 2 的幂利用率低）。

**记忆**：「伙伴=2 的幂分组+上探对半分（分配）、相邻同大小两伙伴空闲就合并（释放）；伙伴=地址相邻同大小相差 2^k 的块；优点快、合并简单、碎片少；缺点内部碎片、只适合 2 的幂」。

**易错**：**伙伴合并**只对**特定伙伴**（地址相邻、同大小、起始地址第 k 位互补）发生，**不是任意相邻两块**；对**非 2 幂**需求会**浪费（内部碎片）**。

---

### 10. 紧凑的概念和所需条件

**核心**：**紧凑（压缩 / Compaction）**是把**分散的小空闲区**合并成**一个大的连续空闲区**，用来**解决外部碎片**、为**大作业**提供连续内存。

**实现**：**移动**内存中已分配的程序，把**所有已分配的信息**移到**内存的一端**（如低地址），使空闲区**集中到一起**。需要**动态重定位**支持（因为程序位置改变，其**逻辑地址→物理地址**映射随之改变）。

**所需条件**：
- 必须采用**动态重定位（运行时装入）**机制（基址寄存器/MMU），因为**程序被移动**后物理地址变化，需要更新映射；**静态重定位/绝对装入**无法移动。
- 需要**向用户进程透明**：进程不知自己被移动。
- **开销**：移动与**更新重定位信息**（页表/基址）需要**时间**，且**只有在内存空闲**时才能做（移动期间进程不能访问）。
- 常与**动态分区**配合，解决**外部碎片**。

**记忆**：「紧凑=移动已分配程序到一端、合并外部碎片成连续大空闲区；需要**动态重定位**支持（运行时移动更新映射）、透明、有开销」。

**易错**：**紧凑需要动态重定位**（运行中能移动）；**静态重定位/绝对装入**程序中**不能移动**；紧凑解决**外部碎片**（不影响内部碎片）。只在**动态分区分配**（连续分配）且**无大块空闲**时考虑。

---

### 11. 基本页式管理相关知识：设计思想、划分、地址映射、页表

**（1）设计思想**
- 把**内存（物理内存）**分成**大小相等的物理页框（物理块/帧 Frame）**；把**进程的逻辑地址空间**也分成**大小相等的逻辑页（页 Page）**；**页和页框大小相等**。
- 进程装入时**无需连续**：各**逻辑页**可分配在**任意物理页框**（离散存储），用**页表**建立映射。进程的**逻辑地址是连续的**，物理上**不连续**。

**（2）对逻辑/物理空间的划分**
- **逻辑地址划分为**：`页号 P = 逻辑地址 / 页大小`，`页内偏移 W = 逻辑地址 % 页大小`。
- **物理地址 = 页框号 f × 页大小 + 页内偏移 W`（`f = 页表[P].页框号`）。
- 页内偏移**不变**（页与页框同大小），只把**页号**换成**页框号**。

**（3）地址映射方式**
1. 由逻辑地址分离出**页号 P 和偏移 W**（页号高位、序号、页大小 2 的幂时直接移位）。
2. 查**页表**：用**页号 P**作索引（页表寄存器 PTBR 指向页表），得到**页框号 f**。
3. 合成物理地址：`物理地址 = f * 页大小 + W`。
4. 检查**页号是否越界**（P 是否小于页表长度）。

**（4）页表的结构、特征及页表项组成**
- **页表**是**页号→页框号（物理块号）**的映射表，由于页表很大，存储在**内存**中，由**页表基址寄存器（PTBR）**指向；每进程一张页表。
- **页表项**组成：**页框号（物理块号）** + **状态位/有效位（是否在内存）+ 保护位（读写执行权限）+ 访问位（最近是否被访问）+ 修改位（是否被改写）** 等。逻辑地址结构为「**页号 | 页内偏移**」。

**记忆**：「页式=物理和逻辑都按等大小页划分、逻辑页离散放任意物理页框、靠页表映射；逻辑地址=页号+偏移、页表基址寄存器定位、查页表得页框号合成物理地址；页表项=页框号+有效位+权限+访问位+修改位」。

**易错**：页式**物理不连续、无外部碎片**（但有**内部碎片**：每页最后一块不满）；**页面大小固定**；页号与偏移分离用**移位/取模**（页大小 2 的幂时位移）。页表**本身放内存**，故有**两次访存**（一次查页表一次访数据）。

### 12. 快表 TLB 的概念、映射方式

**核心**：**TLB（快表 / 联想存储器）**是**高速缓冲（Cache）**，放在 CPU 内部的**联想寄存器（相联存储器）**中，用于**缓存最近用到的页表项**，加快地址转换，减少访问内存查页表的时间。

**概念与映射方式**：
- 由于**页表在内存**，每次访存要先**查页表（一次访存）**再访数据——**两次访存**。TLB 缓存**部分页表项（页号→页框号）**。
- **映射方式**：地址转译时**先用逻辑地址的页号**到 **TLB 中查找**：
  - **TLB 命中**：直接取页框号，合成物理地址（**省去一次访存**）。
  - **TLB 未命中**：再去**内存查页表**，并把该项**装入 TLB**（若 TLB 满，需按替换策略淘汰）。
- TLB 是**相联（内容寻址）**查找，速度快，但容量小（项数有限）；每个页表项通常包含**页号、页框号、有效位/权限位**。

**记忆**：「TLB=联想存储器缓存页表项，命中则免查内存页表、访存快；未命中则查内存页表并装入 TLB；容量小、需替换」。有效**减少平均访存次数**。

**易错**：TLB 命中时**仍有一次访存**（取数据）；未命中时**两次访存**（查页表 + 取数据）。TLB 是**地址转换缓存**，不是**数据缓存**（与 Cache 区别：Cache 缓存**数据**，TLB 缓存**地址映射项**）。

### 13. 包含 TLB 的系统的内存访问过程

**核心**：CPU 每次访存（取指/取数），地址转换流程：
1. **CPU 产生逻辑地址**，分离出**页号 P 和页内偏移 W**。
2. **查 TLB**：用页号 P 在 TLB（联想存储器）查找：
   - **命中**：得到**页框号 f`（并检查**权限/有效位**）→ 直接把 f 和 W 合成**物理地址**。
   - **未命中**：到**内存查页表**（用 PTBR + 页号作索引），读出页表项，得到页框号 f；**检查有效位/权限**；把该页表项**装入 TLB**（可能需要按替换算法淘汰一项）。
3. **合成物理地址**：`物理地址 = 页框号 f * 页大小 + 页内偏移 W`。
4. 用该物理地址**访问 Cache/内存**取数据。

**有效访存时间（EAT）**：设命中率 h，TLB 查找时间 t，内存一次访问 m：
- 若命中（查表+访存）：`h × (t + m)`
- 若未命中（查表+查页表+访存）：`(1 - h) × (t + 2m)`
- `EAT = h×(t+m) + (1-h)×(t+2m) = t + (2-h)×m`。命中共一次访存，未命中两次访存（页表+数据）。

**记忆**：「逻辑地址→查 TLB（命中取页框号合成物理地址、免查内存页表）→未命中则查内存页表并装入 TLB→合成物理地址→访问数据；EAT=t+(2-h)*m」。

**易错**：**命中时一次访存**、**未命中时两次访存**；计算 EAT 时不把**TLB 查找时间**漏掉，且**未命中**要叠加**两次内存访问**。

### 14. 多级页表下的地址访问过程

**核心**：当**页表很大**（单级页表占内存太多），用**多级页表**把页表**分页**，按需装入，节省内存。访问需**逐级查表**。

**过程（两级页表为例）**：
- 逻辑地址分为：**一级页号 P1 | 二级页号 P2 | 页内偏移 W`（三级依次类推）。
- **访问步骤**：
  1. CPU 用 **P1**（在**页目录**中索引，由**页目录基址寄存器 PTBR/CR3** 指向）查**一级页表（页目录）**，得到**二级页表**的**页框号**。
  2. 用 **P2** 在**二级页表**（其基址=上一步得到的页框号）中索引，得到**物理页框号 f**。
  3. 合成物理地址：`f * 页大小 + W`。
  4. 访问数据。
- **访存次数**：N 级页表**未命中基页表/DTLB**时，需 **N + 1 次访问**（N 次查各级页表 + 1 次取数据）；若 TLB/部分页表在缓存中则减少。

**多级页表的优点**：**省内存**（页表本身分页、按需装入），但**访问次数增多**、逻辑地址位数被**拆成更细**（页号分了多级）。

**记忆**：「多级页表=页表再分页、按需装入、省内存；访问=逐级用 P1、P2…查表得到页框号合成物理地址；N 级页表=N+1 次访存（未命中时）」。

**易错**：**多级页表**增加**访存次数**（用空间换/内存省）；逻辑地址字段被拆成**多段**；**页目录基址寄存器**指向第一级。

### 15. 段式管理相关知识：设计思想、段表项、二维地址、优势、碎片、段页式

**（1）设计思想**
- 按**程序的逻辑结构**把**逻辑地址空间划分成若干段**（如代码段、数据段、栈段、堆段），**长短不一**；每段是**一组逻辑上完整的**单元。
- 每段有**段号（段名）**和**段内偏移**；段装入时**不要求连续**，各段分别分配连续物理区（各段内部连续，段间可离散）。

**（2）段表项组成**
- 段表项：**段号 → 基址（段起始物理地址）+ 段长（限长）**，另含**存取权限（读写执行）、访问/修改位**等。
- 段表在内存中，PTBR（段表基址寄存器）指向。

**（3）二维地址结构**
- 逻辑地址 = **段号 S | 段内偏移 W`（二维）。**物理地址 = 段表[S].基址 + W`，并做段长/越界检查。

**（4）段相比页的优势**
- **逻辑清晰**、符合程序逻辑结构，**方便共享与保护**（按段共享/保护，如共享代码段），**便于模块化、动态链接**。
- 段的长度**可按需/可变**，体现**逻辑意义**。

**（5）段与页的外部碎片与内部碎片**
- **分页**：**无外部碎片**、有**内部碎片**（每页最后一块不满）。
- **分段**：**段内无内部碎片**（按需），但**段边界不整、各段长度不一**，会产生**外部碎片**（剩余的小段外碎片），需**紧凑**处理。

**（6）段页式设计**
- 结合段、页：先按**段**划分逻辑空间，再在每段内按**页**划分并装入**离散页框**。
- **逻辑地址 = 段号 S | 段内页号 P | 页内偏移 W`；先查**段表**得该段的**页表基址**，再查**页表**得页框号。
- 优点：**逻辑结构清晰 + 物理离散无碎/省内存**（两者兼顾）；缺点：**访存次数多**（段表+页表+数据），开销大。

**记忆**：「段式=按逻辑结构分成可变长段、段表存基址+段长、二维地址（段号+偏移）、无内部碎片但有外部碎片（需紧凑）、易共享保护；段页式=先段后页、兼顾逻辑与离散省内存、但访存开销大」。

**易错**：**分段有外部碎片（段界不整）**、**分页有内部碎片（页最后不满）**；段页式**访存次数最多**（3~N 次）。**分段便于共享/保护**（整段逻辑），**分页便于管理/无外碎**。

### 16. 虚拟页式存储相关知识：局部性原理、页表项结构、地址转换、文件区与交换区、缺页中断、页框分配

**（1）局部性原理**
- **时间局部性**：刚被访问的指令/数据**不久后很可能再次**被访问（循环、栈）。
- **空间局部性**：刚被访问的指令/数据**附近**的内容很可能**很快**被访问（顺序执行、数组）。
- **依据**：程序访问集中在**少数页面**，故**只装入部分页面即可运行**，缺页时再调入——这就是**虚拟存储**的可行性基础。

**（2）页表项结构（虚拟页式）**
- 逻辑页号对应页表项含：**有效/存在位（是否在内存）、页框号、访问位（Referenced）、修改位（Dirty，写回时用）、保护位（读写执行）、外存地址（换出后位置）** 等。

**（3）地址转换过程**
- 逻辑地址 = 页号 + 页内偏移；查页表（先 TLB）：
  - **命中且在内存**：得页框号合成物理地址。
  - **缺页（页不在内存）**：触发**缺页中断**，调入页面后转换。

**（4）文件区和交换区**
- **文件区**（文件系统管理）：存放文件内容，**连续分配、按簇分配**，访问慢、**换出尽量少**。
- **交换区/对换区**（swap）：存放**换出/对换**的页面，**连续分配、速度快**，用于**虚拟内存**页面置换（对换）。
- 两类区域**用途/管理不同**：文件区面向文件存取，交换区面向**页面对换**。

**（5）缺页中断处理全流程**
1. 访存时**查页表**：发现目标页**不在内存（存在位=0）→ 产生缺页中断**（属于**内部异常/故障**）。
2. 进入**缺页处理**：保护现场；找到该页的**外存地址**（从页表/交换区）。
3. **分配页框**：若内存有**空闲页框**直接使用；否则**按置换算法**选一页**淘汰（换出）**（若被换出页**被修改过**需**写回外存**）。
4. **调入**：从外存（文件区/交换区）把页面**读入分配的页框**，更新页表项（存在位=1、页框号、访问位等），置**有效**。
5. **重执行**：**重新执行**刚才触发缺页的那条指令（因为该指令已因缺页中断被打断/部分执行），此时页表已更新，可正常完成地址转换。

**（6）页框分配的分类**
- **固定分配**：每个进程**固定大小**的页框数（运行期间不变）；分**固定分配局部置换**（只在自己的页框内置换）与**固定分配全局置换**。
- **可变分配**：页框数**随缺页率动态增减**；分**可变分配局部置换**（按缺页率增减本进程页框，置换也只在本进程）与**可变分配全局置换**（置换可在全局，按需从空闲池分配/回收）。**全局置换**更常用（提高利用率）。

**记忆**：「局部性=时间+空间（循环/顺序）；缺页=页不在内存→缺页中断→分配页框（空闲或置换淘汰）→从外存调入→更新页表→重新执行；文件区管文件、交换区管对换；页框分配：固定/可变 × 局部/全局置换」。

**易错**：**缺页中断**属于**内部异常/故障**，**重新执行**该指令（不是从下一条）；**调入页后要重做那条访问**。**交换区**用于**对换/置换**（快、连续），**文件区**用于文件（慢）。**全局置换**整个系统换页，**局部**只在进程内换。

### 17. 页面置换算法：最优、FIFO、LRU、时钟、改进版时钟

> 参考图：《操作系统基础课件6-虚拟存储方法》第 61、63、67、39 页。

**（1）最优页面置换算法（OPT/理想算法）**
- **原理**：选择**将来最长时间不再被访问**的页面置换。**缺页最少、理论最优**。
- **实现**：需要**预知未来引用串**，故**无法真正实现**，只作为**评价其它算法**的下界标准（缺页次数下限）。

**（2）先进先出算法（FIFO）**
- **原理**：置换**在内存中驻留时间最长**（最早进入）的页面；维护链首最老、链尾最新的队列。
- **特点**：**实现简单、开销小**；但**性能较差**（可能与实际使用无关，刚进入的页可能马上就要用），且**可能发生 Belady 异常**（见第 18 题）。

**（3）最近最少使用算法（LRU）**
- **原理**：置换**最近最久未使用**（最长时间没有被访问）的页面。利用**局部性**：过去最久未用的未来少用。
- **实现**：**硬/软计时**；常借助**栈**（每次访问把页面移到栈顶）、**计数器/时间戳**；或用**老化（近似）**。
- **特点**：性能**接近 OPT**，**无 Belady 异常**（堆栈型算法）；但**实现开销较大**（需记录/更新访问次序），硬件支持（需比较频繁）。

**（4）时钟置换算法（Clock/NRU）**
- **原理**：近似 LRU，用**访问位**（引用位）。所有页组织成**循环链表**，指针指向候选页；置换时：
  1. 若指针所指页**访问位=0** → 置换它，指针后移。
  2. 若**访问位=1** → 置为 **0**，指针**后移**继续（给它一次"缓冲"机会），直到找到访问位=0 的页。
- **特点**：**开销小、近似 LRU**，是**操作系统实际常用**；但**不够精确**（只区分"最近访问过与否"）。

**（5）改进版时钟置换算法**
- **原理**：把**访问位 + 修改位**组合，按**置换代价**排序：
  - **（0,0）**：未访问未修改 → **最优置换**（不需写回）。
  - **（0,1）**：未访问但已修改（需写回，代价大，但很少被访问）。
  - **（1,0）**：访问过未修改。
  - **（1,1）**：访问过且修改过 → 最差。
  - **扫描优先选 (0,0)**，一轮找不到再选 (0,1)、(1,0)、(1,1)。
- **特点**：**综合考虑"使用"与"写回代价"**，比普通时钟**更优**（减少写回），实现略复杂。

**记忆**：「OPT=置换未来最久不用（理论下界、不可实现）；FIFO=置换最早进入（简单、有 Belady）；LRU=置换最久未访问（近似 OPT、无 Belady、开销大）；Clock=访问位环形扫描（近似 LRU、常用）；改进 Clock=访问+修改位（0,0 最优、考虑写回代价）」。

**易错**：**OPT 只是理论基准**（需预知）；**FIFO 有 Belady 异常**（LRU/OPT/Clock 属于**堆栈算法**无 Belady）；**LRU 开销大**（需记录次序）；**Clock 是近似 LRU**；改进 Clock **优先置换 (0,0)**（免写回）。

### 18. Belady 现象的概念及可能引发的页面置换算法

**核心**：**Belady 异常（Belady's Anomaly）**指：在**页面置换**中，**分配给进程的物理页框数增加**时，某些情况**缺页次数反而增加**（页面数多反而缺页更多），是**反常现象**。

**原因**：**FIFO 等内存组算法**不是**堆栈（Stack）算法**（其驻留集不一定是"最近 k 个页面"的子集），增加页框导致置换决策变化，产生反常。

**可能引发的算法**：**先进先出（FIFO）**算法**可能出现** Belady 现象。而 **LRU、OPT、Clock 等堆栈型算法**（其驻留集总是"最近访问过的 k 个页面"，属于**堆栈算法**）**不会出现** Belady 现象。

**记忆**：「Belady=页框多反而缺页多；**FIFO 可能出现**；LRU/OPT/Clock（堆栈算法）**不会**」。

**易错**：**FIFO 可能** Belady，**LRU/OPT 不会**；判断依据是**是否堆栈算法**（驻留集是否为最近引用集的子集）。

### 19. 工作集、驻留集概念及工作集置换算法，抖动的含义

**（1）驻留集**
- 进程**当前驻留在物理内存中的页框集合**（已装入的页面）的大小，即分配给进程的**页框数**。

**（2）工作集（Working Set）**
- 在一个**时间窗口 Δ（工作集窗口）**内，进程**实际访问到的页面集合**（最近 Δ 个引用中出现的页面）。它反映进程在某时刻**正在活跃使用**的页面数。
- `工作集大小 WSS` = 窗口 Δ 内不同页面的个数。若**驻留集 ≥ 工作集**，则缺页少；否则缺页多。

**（3）工作集置换算法**
- 基于**工作集**分配页框：使**驻留集 >= 工作集**；当页框超出/不足时，把**不属于当前工作集的页面**置换出去。
- 常与**虚拟内存 + 缺页率**挂钩：**根据缺页率动态调整驻留集大小**（缺页高则增加，缺页低则减少）。

**（4）抖动（Thrashing）**
- **抖动**：进程**频繁缺页**（频繁换页），导致**大部分时间都在处理缺页/页面置换**，真正**执行程序的时间极少**，系统**吞吐量急剧下降**。原因是**驻留集 < 工作集**（内存不足/进程过多），页面**反复淘汰又反复调入**。
- **原因**：**局部性不足**或**进程太多/内存不够**使驻留集小于工作集。
- **解决**：**引入工作集/驻留集控制**（保证进程驻留集>=工作集），**限制多道程序度**（减少并发进程数）、**换出部分进程**（挂起）等。

**记忆**：「驻留集=进程驻留内存页框数；工作集=窗口Δ内访问到的页面集合（活跃页面），驻留集<工作集会抖动；工作集算法按需分配保证驻留>=工作集；抖动=频繁缺页、CPU 空转做换页，源于驻留集<工作集/进程过多」。

**易错**：**抖动**是**频繁缺页**导致**系统吞吐骤降**（不是"死锁"）；**解决**是**保证驻留集≥工作集、降低多道程度**。**工作集是动态**（随时间窗口变化），**驻留集是被分配**（可由 OS 调整）。

## 第四章 文件系统

### 1. 文件系统解决的问题

**核心**：文件系统负责**对文件的组织、存取、保护与磁盘空间管理**，把用户视角的"文件"映射到磁盘上的物理存放。它解决：

- **文件的命名与组织**：用**目录/路径**组织文件，方便用户按名存取。
- **文件的存储与分配**：如何把文件内容**分配到磁盘块**（连续/链式/索引）、记录文件**物理位置**（FCB/inode）。
- **存取与读写**：提供**open/read/write/close** 等接口，完成**按名定位、建立/删除、读/写**。
- **空间管理**：管理磁盘**空闲空间**（位图、空闲链等），分配与回收。
- **文件保护与共享**：**存取控制**（权限）、**链接**（硬/软链接）实现共享。
- **性能与可靠性**：**磁盘缓存/缓冲**、一致性、容错。

**记忆**：「文件系统解决：命名组织（目录）、存放分配（FCB/inode）、读写接口、空闲管理、保护共享、性能可靠性」。

**易错**：文件系统**向上**给用户一个**逻辑/虚拟**视图（按名、层次、连续的"流"），**向下**把它映射为**物理磁盘块**；核心是**目录 + 文件分配（映射）+ 空闲管理**。

---

### 2. 逻辑文件：用户视角下的文件

**核心**：**逻辑文件**是从**用户/程序角度**看到的文件——一个**有名字、有逻辑结构**的**数据集合**，不关心物理存放。用户看到的是**按逻辑结构**组织的**字节流/记录**。

- **逻辑结构**（用户视角）：
  - **无结构文件（流式文件）**：由**一串字节**组成，无记录边界（如源代码、可执行文件），以**字节**为单位。
  - **有结构文件（记录式文件）**：由若干**记录**组成，记录可有**定长/变长**，含**顺序文件、索引文件、索引顺序文件、散列（哈希）文件**。

**记忆**：「逻辑文件=用户视角的、按名称与逻辑结构（流式/记录式：顺序、索引、索引顺序、散列）组织的文件；用户只关心内容与结构，不关心磁盘位置」。

**易错**：把"**逻辑文件**（用户视角，有结构/字节流）"与"**物理文件**（磁盘上的块、FCB/inode 记录）"分开；用户**看到的**是逻辑文件，**操作系统管理的**是物理映射。

---

### 3. 物理文件：文件在磁盘中的存放

**核心**：**物理文件**是文件内容在**磁盘外存上的实际存放方式**；由文件系统通过**分配策略**（连续/链式/索引）把文件的**逻辑块**映射到**磁盘物理块**，并通过 **FCB / inode（索引节点）**记录映射关系。

- **分配方式（映射）**：**连续分配、隐式链接、显式链接（FAT）、索引分配（单级/多级/混合）**。
- **物理地址**：由**盘块号**（柱面/磁道/扇区或**线性块号**）表示；操作系统把**块号 → 物理位置**（柱面/磁道/扇区）。
- 物理文件**不一定连续**（链式/索引），也可能连续（连续分配）；映射表（FCB/inode 中的地址指针/索引表）决定了如何找到文件的各块。

**记忆**：「物理文件=磁盘上的实际存放，靠分配策略把逻辑块映射到物理块，由 FCB/inode 记录地址（共享元数据+存储块）；分连续/链式/索引」。

**易错**：**物理文件的地址**由**文件分配策略**决定，且**存储**需要）**元数据（FCB/inode）+ 数据块**两部分；物理结构影响**存取效率、碎片、共享、随机访问**。

---

### 4. 文件系统视角下的磁盘空间、访问磁盘的方式

**核心**：文件系统把**磁盘空间**看作**一系列盘块（块）**，并按**块**分配/管理；访问磁盘要**按块**进行，且**寻道 + 旋转延迟 + 传输**三步。

- **磁盘空间划分**：磁盘被分为**扇区 → 磁道 → 柱面 → 盘面**；对外以**线性块号**（逻辑块号）统一编址；文件系统把块号映射到**物理位置**。
- **分配单位**：文件系统以**块**为**基本分配/存取单位**（块大小通常为 512B~4KB 的整数倍），按**逻辑块号**连续或不连续分配。
- **访问方式**：每次**读/写**一组块，数据在**磁盘 ↔ 缓冲区/内存**之间**以块为单位**传输；访问时间 = **寻道时间 + 旋转延迟 + 传输时间**（见磁盘题）。

**记忆**：「文件系统把磁盘看作盘块的集合、以块为分配单位、逻辑块号↔物理块号映射；访问耗时=寻道+旋转延迟+传输」。

**易错**：文件系统**以块为单位**（不是字节），某文件**最后一块可能不满**（内部碎片）；访问磁盘**不能随机按字节**，需按**块**读入。

---

### 5. 磁盘缓存技术

**核心**：**磁盘缓存（Disk Cache / 缓冲区）**在**内存**中保留**最近读/写的磁盘块**，使后续**访问命中时免去磁盘 I/O**，利用**局部性**减少实际访问磁盘次数。

- **实现**：内存设一块**缓冲区（buffer cache / page cache）**，用 **LRU 等**替换算法管理。读请求**先查缓存**，命中则直接给；未命中才访问磁盘并装入缓存。
- **写回策略**：**写直达（write-through）**（立即写磁盘，安全但慢）或**写回（write-back）**（先写缓存，延迟刷新到磁盘；快但需**脏页**管理、**一致性**风险）。
- **效果**：显著**提高 I/O 性能**（利用时间/空间局部性），降低**寻道/旋转/传输**开销（合并访问）。与**文件系统缓冲（buffer）**配合。
- 与**I/O 缓冲**区别：磁盘缓存在**文件系统/页缓存**层，缓存的是**文件页/块**；I/O 缓冲用于**设备与内存间**数据传输。

**记忆**：「磁盘缓存=内存保留最近磁盘块（LRU），命中免 I/O、局部性；写直达安全慢、写回快需脏页；显著降 I/O 开销」。

**易错**：磁盘缓存**缓存的是磁盘块/页**（文件数据），非**PCB/页表**；**写回**有**数据丢失**风险（断电），需**刷新**；缓存**命中率**决定收益。

---

### 6. 目录系统、目录项、索引节点概念

**（1）目录系统**
- **目录**是**一个特殊的文件**，包含一组**目录项**；目录系统把文件**按层次组织**，实现**按名存取**。典型**树形（层次）目录**：根目录 + 各级子目录。

**（2）目录项**
- **目录项（Directory Entry）**：描述文件，包含**文件名**和**索引节点号**（指向 inode），还可含**类型、权限**等信息。目录实际上是一个**文件名→ inode** 的映射表。
- 通过目录项，根据文件名找到对应的 **inode**（索引节点），进而得到文件的**物理地址、属性**。

**（3）索引节点（inode）**
- **索引节点**是**文件的元数据**，存放**文件属性**（大小、权限、所有者、时间）与**文件物理块地址**（直接/间接指针）等信息；**文件名与 inode 分离**（文件名在目录项，属性/地址在 inode）。
- 一个文件有一个 inode；打开后 inode 载入内存（内存 inode）。**目录本身也有自己 inode**。

**记忆**：「目录=特殊文件、含目录项；目录项=文件名+inode 号；inode=文件元数据（属性+地址）；目录把"名字"映射到"inode"，实现按名存取」。

**易错**：**目录项存文件名与 inode 号**，**真正的文件属性与物理地址在 inode**；**分离**设计使**硬链接**方便（多目录项指向同一 inode）。

### 7. 根据路径完成目录检索全过程

**核心**：按**路径名**（如 `/usr/bin/foo`）找到文件，需**逐级搜索目录**。过程可参考零壹课件7（第 24–27 页，目录项/目录）。

**过程（树形/层次目录）**：
1. 从**根目录**（绝对路径）或**当前目录**（相对路径）开始。
2. 读**当前目录**的 inode → 读**目录数据块**，在其中**按文件名**查找**目录项**（顺序/二分/散列）。
3. 由目录项得到**下一级目录/文件的 inode 号**。
4. 重复"读目录 → 查目录项 → 得 inode 号"逐级向下，直到**最后一级**——得到**目标文件的 inode**。
5. 由目标 inode 得到文件属性与**物理块地址**，完成**按名定位**。

**要点**：每级查找要**读目录数据块**（可能要多次 I/O）；用**当前目录/路径缓存**与**目录信息缓存**可加速；**inode 常驻内存**的中介（打开后）。

**记忆**：「绝对/相对路径 → 逐级"读目录→按名查目录项→得 inode 号"→ 到最后得目标 inode → 得属性/地址。目录检索本质是"名字→inode"的多级查表」。

**易错**：**目录检索**每级都要**读目录块**（I/O 开销）；**绝对路径从根目录**开始，相对路径从**当前目录**；硬链接下**多个路径名指向同一 inode**，检索都最终到同一 inode。

---

### 8. 软链接和硬链接的概念

（1）**硬链接（Hard Link）**
- 多个**目录项**指向**同一个 inode**（文件名不同，inode 号相同）。它们**共享同一个**文件数据和**元数据（inode）**；inode 有**引用计数**，**删除一个不删除**（计数减1），**最后一个删除**才真正释放。
- **特点**：同一文件系统内，**不能跨文件系统**（因为不同文件系统 inode 含义不同）、**目录不能硬链接**（防环）；删除不影响原数据（只要计数>0）。

（2）**软链接（符号链接 Symbolic Link）**
- 一个**独立的小文件**，其**内容存放的是目标文件的路径名**（不是 inode）。软链接有**自己的 inode**，指向的目标是**另一个文件/目录**的**路径**。
- **特点**：**可跨文件系统**、**可指向目录**；但若**目标被删除/移动**则**软链接失效**（悬空）；链接减计数只在链接文件本身。访问软链接时**系统按路径重定向**。

**记忆**：「硬链接=多个目录项指向同一 inode、共享数据、同文件系统、不能链目录、删除只是减计数；软链接=一个存"目标路径"的小文件、独立 inode、可跨系统、目标删除则失效」。

**易错**：**硬链接删除**不影响数据（引用计数>0），**软链接删除目标则失效**；**硬链接不能跨文件系统**、**软链接可以**；**软链接**是"路径别名"，**硬链接**是"同一个文件（inode）"。

---

### 9. 目录实现方法

**核心**：目录实现（文件系统如何存储/查找目录项）分**线性、散列、B 树/树**等。

（1）**线性表/顺序数组**：把所有目录项**顺序存储**成表，按**线性查找**。
- 简单；但**查找慢**（O(n)），插入/删除需移动。

（2）**散列（哈希）表**：以**文件名→哈希值**定位目录项在哈希表中的位置。
- 查找**快（接近 O(1)）**；但需要处理**哈希冲突**，不适合**排序/按序列出**。

（3）**树（如 B 树/B+树）**：目录项按**树结构**组织（常用**B+ 树**），支持**按序/范围**访问与高效查找，**动态平衡**（如 ext4 目录）。

（4）其它：**索引表、链表**等（目录项链）。
- 文件系统往往**小目录用线性/散列、大目录用 B+树**。

**记忆**：「目录实现：线性表（简单慢）、哈希（快、冲突）、B+树（平衡、按序、动态）、链表等；现代大目录用 B+树」。

**易错**：目录**本身也是文件**（有 inode、有数据块）；**哈希**目录不适合**顺序遍历/范围查询**；**线性**目录插入删除慢。

---

### 10. 文件打开相关知识（两种设计）

**（1）打开全过程**
- 用户调用 `open(path, flags)` → 系统**按路径检索目录**（见第 7 题）找到**目标文件 inode** → 把 **inode 读入内存（内存 inode）** → 在**系统打开文件表**中登记（加引用）；若打开成功，返回**文件描述符/文件句柄**，**在用户进程打开文件表中登记**。
- **路径检索 → 读 inode 入内存 → 系统表登记 → 用户表登记返回 fd**。

**（2）内存 inode 的特点**
- 把磁盘 inode **拷入内存**（**快、常驻**），包含**访问需要的信息**（属性、物理块指针、引用计数）；**修改后写回**。内存 inode 比磁盘 inode 快，且**同一文件多次打开**时**共享**内存 inode（引用计数+1），避免重复读磁盘 inode。

**（3）用户级打开文件表与系统级打开文件表**
- **系统级打开文件表（系统打开文件表）**：**全校**的打开文件登记（每个打开的文件一项，含 inode、偏移、计数、读写权限）；**每进程/每用户**共享或登记**文件对象**。
- **用户级打开文件表（每进程打开文件表）**：每个进程一份，列出**本进程打开的文件**（文件描述符/表项指向**系统表**的对应文件对象）。
- 关系：**进程表项 → 系统打开文件表项**（一个文件被多进程打开，系统表可一项**共享**，进程表各自指向；**文件偏移**可能在**进程表项**（每进程独立偏移）或在**文件表项**（共享）——两处差异意味**多进程共享文件描述符**时偏移共享）。

**（4）打开文件的系统调用接口特点**
- **系统调用接口**：`open`（创建文件表项/返回 fd）、`close`、`read/write` 用 fd 定位打开文件；**只传 fd**（不再每次按路径检索），**提高效率**。
- 每进程一个**用户打开文件表**，表项含**fd、文件指针（偏移）、指向系统表的指针**；打开后可**多次读写**（偏移自动推进）。

**记忆**：「open=路径检索→读 inode→系统表登记→进程表登记返回 fd；内存 inode=磁盘 inode 拷贝、常驻、多开共享计数；进程打开表（每进程）→ 系统打开表（全校、文件对象）；接口用 fd 免重复检索、有独立/共享偏移」。

**易错**：**文件偏移**可能在**进程打开表**（每进程独立）或**系统表**（多进程共享），影响**多进程读写位置**；**fd 本质是进程打开表项的索引**；**close 只是减引用**（系统表项真正删除要等计数为 0）。

---

### 11. 文件关闭

**核心**：`close(fd)` 关闭一个打开文件。
- **过程**：从**用户打开文件表**中**删除该 fd 表项** → 文件类的**引用计数减1**；若该文件**不再被任何进程打开**（计数为 0）→ 从**系统打开文件表**移除该文件对象（并**写回 inode/刷新缓冲**）。
- **作用**：**回收资源**（文件表项、内存 inode 引用）、**确保缓冲数据写回**、防止资源泄露。
- **未关闭**会造成**文件描述符/表项泄漏**（资源耗尽）。

**记忆**：「close=删进程表项→引用计数-1→若无进程打开则移出系统表并写回 inode/刷新；回收资源、写回缓冲」。

**易错**：关闭是**减引用**，**不是删除文件**（文件数据仍在磁盘）；只有**最后关闭**才真正移除系统表项/刷新。

---

### 12. 文件删除

**核心**：`unlink/remove` 删除文件。
- **过程**：找到文件名对应**目录项、inode** → **从目录中移除该目录项** → inode **引用计数减1** → 若**计数=0**（无人链到它）则**回收 inode 与文件数据块**（标记**磁盘块空闲**），并**清空目录项**。
- **注意**：删除的是**目录项/链接**（减计数），**并不立即释放还在打开/被硬链接使用的文件**；**硬链接文件**删除一个名让计数减1，其余仍有效。
- 被**打开但未关闭**的文件删除后，其 inode 可能**延迟删除**（直到关闭）。

**记忆**：「delete=删目录项→inode 计数-1→计数为0才回收 inode 与数据块；硬链接只减计数；删除目录项≠立即释放还在用的文件」。

**易错**：**硬链接**删除只是**减引用**；**未关闭仍在打开**的文件删除后数据**延迟释放**；**删除不回收数据块直到引用计数为0**。

### 13. 文件创建

**核心**：`create/open(O_CREAT)` 创建文件。
- **过程**：在**父目录**中**分配一个目录项**（文件名）→ **分配一个 inode**（初始化属性、大小、地址等）→ 建立**目录项→inode** 绑定 → 写入磁盘。
- 若**同名文件已存在**则可能覆盖/报错；**分配空闲磁盘块**用于数据（创建时通常仅建元数据，数据块按需分配）。

**记忆**：「create=分配目录项 + 分配并初始化 inode + 目录项绑定 inode；按需/按需分配数据块」。

### 14. 文件读写相关知识

**（1）具体过程**
- `read(fd, buf, n)`：由 fd 找到**打开文件表项** → 用**文件偏移**定位**逻辑块** → 通过 **inode 的物理块映射**得到**磁盘物理块** → **读入缓冲区/用户 buf**，**偏移后移**。
- `write(fd, buf, n)`：定位 → 分配**物理块**（若新块）→ 拷贝数据到缓冲 → 写回（或延迟写回），**更新 inode**（长度、修改时间）、偏移后移。
- 读写在**用户态与内核态之间拷贝**（内核缓冲），经**系统调用**。

**（2）系统调用接口特点**
- **按 fd**（文件描述符）访问（打开时得到），无需每次按路径检索；**每次读写用偏移**（共享/独立）。
- **同步/阻塞**（read/write）为主；还有**异步、mmap** 等。读写以**字节/块**为单位，但磁盘以**块**为单位（缓冲合并）。

**（3）文件指针（文件偏移量）的概念和用处**
- **文件偏移量（文件指针）**是一个**当前读写位置**（从文件开头的偏移），**每个打开文件每次读写后自动后移**，使连续读写顺序推进。
- **用处**：支持**随机访问**（`lseek` 改变偏移）、**顺序读写**；偏移在**进程打开文件表**（每进程独立）或**系统表**（共享）中，决定**多进程/多线程**读到哪儿。

**记忆**：「read/write=fd→打开表项→用偏移定位→经 inode 映射得到物理块→缓冲拷贝→偏移后移；接口用 fd（免路径检索）、按偏移访问；文件指针=当前读写位置，支持顺序/随机访问（lseek）」。

**易错**：**偏移是"字节位置"**（不是块号）；**每次读写后偏移自动前进**；**lseek 改变偏移**实现随机访问；偏移**共享与否**取决于进程表项/系统表项设计。

### 15. 文件的第一层保护和第二层保护，第一层保护的具体方案

**核心**：文件保护分**两层**：
- **第一层保护（存取控制/权限）**：控制**谁（用户/用户组）可以以什么方式（读/写/执行）**访问文件——**外层访问权限**。
- **第二层保护（某些情况下=存储介质/物理层或口令/访问记录等）**：如**口令、加密、完整性校验**，或防止**物理/数据损坏**的保护（备份、容错）。

**第一层保护的具体方案（存取控制）**：
1. **存取控制矩阵（访问控制矩阵）**：行=用户，列=文件，格=权限（读/写/执行/管理）。**本质**；但**太大**难以实现。
2. **访问控制列表（ACL）**：**每个文件**列一张表（哪些用户/组有何权限）；**针对文件**列出。灵活但**表长**。
3. **用户/用户组标识 + 存取权限**（Unix 风格）：**r/w/x** 三类 + **属主/组/其他** 三组，每个文件用**9 位**（或用**3 位**）表示权限（如 `rwxr-xr--`）。
4. **口令（第一层也可作口令）**、**加密**（防泄露）等辅助。

**记忆**：「第一层=存取控制（谁以何方式访问）；方案=访问控制矩阵、ACL、用户/组+读写执行权限（Unix rwx 属主/组/其他）；第二层=口令/加密/备份容错等（防止越权与数据损坏）」。

**易错**：**第一层保护**是**访问权限控制**（何时/谁/何方式能访问）；**第二层保护**偏**口令/加密/完整性/容错**；**ACL 存取控制矩阵**都是"权限"层面，比"口令/加密"更偏**访问授权**。

### 16. 文件逻辑结构：流式文件、顺序文件、散列文件、索引文件、索引顺序文件概念

**核心**：文件**逻辑结构**（用户/逻辑视角）：
- **无结构（流式）文件**：**字节/字符流**，无记录边界，按字节存取（如源程序、文本）。可见性最高，简单。
- **顺序文件**：**记录按顺序**排列，记录可为定长/变长；适合**顺序访问**（顺序存取快），**随机访问需定位**（定长可计算，变长麻烦）。
- **索引文件**：除记录外**建一个索引表**（记录键→地址/偏移），支持**按关键字快速查找/随机访问**；索引表可多级。
- **索引顺序文件**：**记录有序 + 建索引**（每若干记录一个索引项，索引+顺序）；**兼顾顺序与随机**（列表+索引块），按**块/组**索引。
- **散列（哈希）文件**：用**哈希函数**把记录**键→存储地址**，**直接寻址**、查找快；但有**冲突**（溢出处理），一般用于**随机访问/直接存取**。

**记忆**：「流式=字节流；顺序=记录按序（顺序存快）；索引=加索引表（随机快）；索引顺序=有序+索引（兼顾）；散列=哈希直接寻址（最快、需处理冲突）」。

**易错**：**逻辑结构**是**用户/逻辑层面**（记录、字节、键），与**物理分配**（连续/链式/索引分配）不同；**散列**用哈希定位，**冲突**处理（溢出）是重点；**索引顺序文件**是**顺序+索引**的折中。

### 17. 文件分配方法的设计思路及访问 k 号文件块需要多少次 I/O

**核心**：**文件的物理分配方法**决定"如何把逻辑块映射到物理块"，从而影响**随机访问、顺序访问**的**I/O 次数**。

**（1）连续分配**
- 文件**连续占一片磁盘块**；FCB 记录**起始块号 + 长度**。
- **访问 k 号块**：`物理块号 = 起始块 + k`，**直接计算**——**只需 0 次额外 I/O**（1 次读到该块即可，若已知起始块）。支持**顺序+随机**都快。
- **缺点**：文件**扩展难**（需前/后连续空间）、**外部碎片**、需**紧凑**。

**（2）隐式链式分配**
- 文件各块用**指针链接**（每块头部存下一块号）；FCB 存**首块号+末块号**。
- **访问 k 号块**：从**首块**开始**逐个跟指针**——**需 k 次 I/O**（前 k 块各读一次，才能到第 k 块）。**随机访问慢**（只适合顺序）。
- **缺点**：**只能顺序访问**，**指针占空间**、**不便于随机**、**稳定性/一致性差**。

**（3）显式链式分配（FAT 方式）**
- **FAT（文件分配表）**一张表，**每个磁盘块一项**，记录**下一块号**（类似"指针表放内存"）；FCB 存**首块号**。
- **访问 k 号块**：从**首块号**，查 FAT **k 次**（在**内存**中查，FAT 常驻，**不算磁盘 I/O**）→ 得到 k 号块物理位置 —— **随机访问较快**（查 FAT 在内存，免磁盘）。实际读该块**1 次磁盘 I/O**。
- **优点**：**支持随机访问**（FAT 在内存/缓存）、**无外部碎片**、扩展易；**缺点**：FAT 表**可能很大**。

**（4）索引分配（单级/多级/混合）**
- 文件把**所有块的索引**存到**索引块**（inode 中放索引块指针）。**单级**：一个索引块存所有块号；**多级**：索引块再指向索引块；**混合**：直接+一级间接+二级间接+三级间接（如 UNIX inode）。
- **访问 k 号块**：**单级**：读**1 个索引块**（I/O）+ 1 次读数据 = **2 次**（索引块+数据块）；**多级**：读**多级索引块（m 级）** + 数据块 = **m+1 次 I/O**；**混合**：若在直接区（前 10 块）**0 次索引 I/O**，一级间接**1+1=2 次**，二级间接**2+1=3 次**…
- **优点**：**支持随机访问、无外部碎片、便于共享/动态扩展**；**缺点**：**索引块占用空间、多级访问 I/O 多**。

**记忆**：「连续：起点+长度，访问 k 块**0 次额外 I/O**（算地址）。隐式链：**k 次**（从头跟指针）。显式链 FAT：查 FAT 在内存**不算 I/O**、随机快。索引：单级**1 次索引 I/O+数据**=2 次，多级 m 级=**m+1 次**（混合直接区优先）」。

**易错**：**隐式链式**随机访问要**k 次 I/O**；**FAT 方式**随机访问快（FAT 在内存，查 FAT 不算磁盘 I/O）；**索引分配**单级访问 = **索引块 + 数据块**（2 次），多级按级+1；**混合索引**优先用**直接区/一级**等（UNIX 典型）。

### 18. 文件系统外存布局

**核心**：外存（磁盘）在**逻辑格式化**后形成**文件系统的布局**，大致知道**各个部分是干什么的**即可。

**典型布局（从起始到末尾）**：
- **引导块（引导区）**：存放**启动 OS** 的引导程序（磁盘第一个扇区/MBR 分区表）。
- **超级块（superblock）**：文件系统元数据——**文件系统参数**（块大小、块数、空闲块、inode 数、挂载点状态等），是**文件系统的心脏**。
- **inode 表（i-node table）**：存所有**inode**（文件元数据）的区域，**固定数量/大小**（创建文件系统时划分）。
- **数据块区（数据区）**：存放**文件数据、目录内容**的盘块。
- **空闲块管理区**：如**位图/空闲表**（跟踪空闲 inode 与空闲数据块）。
- 还有**目录区**（根目录等，也是数据块的一部分）。

**要点**：布局顺序大致为 **引导块 → 超级块 → inode 表 → 空闲管理 → 数据块区**；各文件系统（FAT、ext、NTFS）具体布局略有差异，但都有"**引导 + 元数据（超级块/inode 表）+ 空闲管理 + 数据**"。

**记忆**：「外存布局≈引导块 + 超级块 + inode 表 + 空闲管理 + 数据块区；超级块管全局参数、inode 表管文件元数据、数据区放内容」。（参考：零壹课件8 第 100 页「逻辑格式化」）

### 19. 空闲磁盘块管理方法的实现（分配、回收）、特点优劣势

**（1）位图法（Bitmap / 位示图）**
- **实现**：用一个**位数组**，每一位对应**一个磁盘块**（1=占用，0=空闲）；inode 和数据块各一位图。
- **分配**：找**为 0 的位**置 1；**回收**：将对应位置 0。
- **特点**：**查找空闲快（位运算）、易于连续分配、空间小**；缺点：**查找大块连续空**需扫描，位图需**常驻内存/部分缓存**。

**（2）空闲表法**
- **实现**：**空闲表**登记每段**连续空闲块**的（起始块号，块数）。
- **分配**：在空闲表中找**合适大小的空闲区**（可配合首次/最佳/最坏适应）；**回收**：把回收块并入空闲表（合并相邻）。
- **特点**：便于**连续分配**；缺点：表可能变化（插入/删除），查找合并成本。

**（3）空闲盘块链**
- **实现**：把**空闲块**用指针**链成链表**（每块存下一空闲块号）。
- **分配**：从链头取一块；**回收**：插入链头。
- **特点**：简单、灵活；缺点：**查找慢**（需遍历）、连续分配难（要遍历找连续块）。

**（4）空闲盘区链**
- **实现**：把**连续空闲盘区**（不是单个块）作为**链**的节点，每个节点记录「起始块、长度、下一个盘区」。
- **分配**：按大小找盘区；**回收**：合并相邻盘区并入链。
- **特点**：比空闲块链**更快**（按区/段）、利于**连续分配**；缺点：实现较复杂、需维护盘区间合并。

**（5）成组链接法**
- **实现**：**分组**把空闲块组织成**链表/树**（避免单链表太长），把空闲块分成**若干组**，每组用一个**"空闲块号表" + 链接到下一组**（如每 100 块一组的首块存下一组首块号）。
- **分配**：从**当前组**中取块，组内取完则取**下一组**（把下一组首块作为新"头"）；**回收**：先填满当前组，满则新开一组链上。
- **特点**：**适合大容量磁盘**、查找/分配/回收**较快**、避免单链过长；是**UNIX** 常用方法；实现**较复杂**。

**记忆**：「位图=位数组（快、小，找大块难）；空闲表=登记连续区（利连续分配）；空闲块链=单块链（简单慢、难连续）；空闲盘区链=按连续盘区链（快、利连续）；成组链接=分组链（大容量、快，如 UNIX）」。

**易错**：**空闲盘区链** vs **空闲块链**：前者按**连续区**链（利于连续分配、快），后者按**单块**链；**成组链接**是为**大磁盘**优化（分组，避免长链），UNIX 使用；**位图**适合**连续分配**但找大块要扫描。

### 20. 磁盘物理格式化、磁盘分区、逻辑格式化的概念，区分逻辑格式化和操作系统初始化

**（1）磁盘物理格式化（低级格式化）**
- 把磁盘**划分成扇区、磁道、柱面**，在扇区**写入**（扇区头的**标记/序号**、错误检测**ECC**），使磁盘**能读写**。出厂/新盘做。

**（2）磁盘分区**
- 在物理格式化基础上，把磁盘**划分为一个或多个逻辑分区**（每分区是独立逻辑盘），写入**分区表**（MBR/GPT），每个分区可安装不同文件系统/OS。

**（3）逻辑格式化（高级格式化）**
- 在**分区上建立文件系统**：**写引导块、建立超级块、inode 表、空闲管理、目录结构**，并**清空/初始化**数据区。**不同的文件系统对应不同的逻辑格式化方法**（因此又称"安装文件系统/构建文件系统"）。逻辑格式化后文件系统才能被使用。

**区分逻辑格式化和操作系统初始化**：
- **逻辑格式化**：建立**文件系统结构**（元数据、目录、空闲块、inode 等），是**文件系统建立**。
- **操作系统初始化（安装 OS）**：**划分分区、逻辑格式化**后，还要**安装引导程序、操作系统内核**、配置启动项等，使**OS 能启动**。这是**OS 环境建立**（逻辑格式化是**基础**，还要装引导/内核/驱动）。

**记忆**：「物理格式化=划扇区磁道柱面、写扇区头 ECC（低格）；分区=划逻辑分区、写分区表；逻辑格式化=在分区建文件系统（超级块/inode/目录/空闲结构、清数据）；OS 初始化=装引导+内核+配置，让系统启动（逻辑格式化是其中一个环节）」。

**易错**：**逻辑格式化 ≠ 物理格式化**；**逻辑格式化**=建立文件系统；**操作系统初始化更多于逻辑格式化**（还要装引导/内核）。顺序：**物理格式化 → 分区 → 逻辑格式化**（→ 装 OS/初始化）。

### 21. 虚拟文件系统和文件系统挂载的概念

**（1）虚拟文件系统（VFS）**
- 在 **OS 内核**提供**统一文件系统接口**，**屏蔽不同文件系统**（ext、FAT、NTFS、网络文件系统等）的差异，让**上层应用**用**同一套系统调用**（open/read/write）访问任何文件系统。
- VFS 用**一组统一的数据结构/操作**（**超级块对象、inode 对象、目录项对象、文件对象** + **vnode/伪文件系统**）抽象；把**具体文件系统**实现成**一套操作函数**（通过**函数指针**注册），VFS 派发到对应文件系统。
- **特点**：**跨文件系统统一接口、可挂载多种 FS、透明**。

**（2）文件系统挂载（Mount）**
- 把**已格式化的文件系统**（在某个**块设备**上）**安装到目录树**的**挂载点（mount point）**（一个目录），使该文件系统的文件**出现在**挂载点下。
- **过程**：读**超级块**、建立**挂载点与文件系统的关联**（在 VFS 中登记），之后访问挂载点下的路径就**转由该文件系统**处理（VFS 分派到下层 FS）。
- **卸载（unmount）**：解除绑定，刷新缓冲。非空/占用时不能卸载。
- 挂载点通常是**空目录**；挂载使**不同文件系统**成为**目录树的一部分**（如 `/mnt/usb`，`/home` 独立分区）。

**记忆**：「VFS=内核统一接口，用 superblock/inode/dentry/file 对象抽象、屏蔽不同 FS、统一系统调用；挂载=把已格式化 FS 绑到目录树挂载点、登记到 VFS，使路径访问交给该 FS」。

**易错**：**挂载点**是**一个目录**（挂载后该目录映射到新 FS 的根）；**VFS**是**内核层抽象**，不是具体文件系统；**挂载/卸载**需**刷新缓冲**、占用时**不能卸载**。

---

### 22. 文件系统层次结构：知道每层具体做了什么工作

**核心**：文件系统从**用户系统调用**到**磁盘 I/O** 划分**层次**，各层职责：

1. **用户层 / 应用层**：用户通过 **系统调用（open/read/write/close）** 提出文件访问请求。
2. **文件系统接口层（VFS/系统调用接口层）**：接受**系统调用**，**按名字/路径**定位目录（**路径解析**），把"名字"转为**inode/文件对象**。
3. **文件系统（逻辑文件系统/目录管理）层**：管理**目录树、FCB/inode**、**文件逻辑结构**、**打开/关闭**；**负责按名找文件、维护打开文件表**。
4. **文件组织（文件分配）层**：管理**文件的物理分配**（连续/链式/索引），**把逻辑块映射到物理块**（逻辑块号→物理盘块号）。
5. **缓冲（缓冲区管理）层**：**磁盘缓存/缓冲**、I/O 调度，把**块**读入/写回；**减少磁盘访问**。
6. **设备驱动 / 磁盘设备层**：把物理块号**转换为磁盘地址（柱面/磁道/扇区）**，**驱动磁盘**，执行**真正的**磁盘读写（含磁盘调度、DMA 等）。

**记忆**：「用户→系统调用接口（路径解析/名字→inode）→逻辑文件系统（目录/FCB/打开表）→文件组织（逻辑块→物理块映射）→缓冲层（缓存/调度）→设备层（物理地址+磁盘驱动）」。

**易错**：**路径解析**在**接口层**；**物理块映射**在**文件组织层**；**缓冲/缓存**层优化 I/O；**最底层**才是**设备驱动**（真正机械动作）。

### 23. 内存映射文件相关知识

**（1）系统调用接口和参数**
- **`mmap(addr, len, prot, flags, fd, offset)`**：把文件（段）**映射到进程地址空间**，此后**访问内存==访问文件**。
  - `addr`：期望映射地址（通常 NULL，由系统选）；`len`：映射长度；`prot`：权限（读/写/执行）；`flags`：**MAP_SHARED**（映射到共享，写回文件，可用于共享内存）或 **MAP_PRIVATE**（写时复制，不写回文件）；`fd`：文件描述符；`offset`：文件内偏移。
- **`munmap`**：解除映射；还可配合 **`msync`**（强制写回）。

**（2）具体功能**
- **文件内容直接映射到进程虚拟地址空间**，通过**页式管理**按需从文件加载对应页；**读写文件就像操作内存**（读写内存页面），减少**read/write 系统调用和拷贝**（免内核缓冲拷贝），**效率高**。
- 依赖**虚拟内存/缺页**：访问未调入的**页**时**缺页中断**从文件读入；**MAP_SHARED** 的**写**最终写回文件。

**（3）如何利用内存映射文件实现多进程共享内存**
- 多个进程用 **`mmap(..., MAP_SHARED, fd, ...)`** **映射同一个文件/共享段**到各自的地址空间；因为**同一个物理页**被映射进**多个进程**，各方**读写**映射地址等价于访问**同一块内存**（共享文件/共享内存）。
- 以此实现**共享内存**（`shm_open`+`mmap(MAP_SHARED)`），配合**信号量/锁**同步。

**（4）进程地址空间主要构成**
- 进程虚拟地址空间由：**代码段、数据段、堆、栈、共享库（mmap 区域）、环境/参数**，以及**映射（mmap）区**、**内核空间（高地址）**组成。内存映射文件占**映射区**（如 mmap 区域），由**页表/缺页**管理。

**记忆**：「mmap(addr,len,prot,flags,fd,off)：映射文件到地址空间；MAP_SHARED 写回、MAP_PRIVATE 写时复制；多进程 MAP_SHARED 映射同一文件=共享内存（免拷贝、快）；进程地址空间含代码/数据/堆/栈/mmap 区/内核区，mmap 靠缺页按需加载」。

**易错**：**MAP_SHARED** 写会**写回文件**（可用于共享内存），**MAP_PRIVATE** 改动**不写回**（写时复制）。内存映射**免 read/write 拷贝**、由**缺页**按需调页，但**小文件/随机**未必更好。

### 24. 磁盘相关知识

**（1）磁盘结构（最好画草图）**
- 磁盘由**若干盘面（platter）**组成，每面**上下**读写（可单/双面），用**磁头（head）**读写。
- **磁道（track）**：每个盘面上的同心圆环；**柱面（cylinder）**：**所有盘面同一半径**的磁道集合（同柱面读写**不移动磁头**）。
- **扇区（sector）**：磁道上被划分的最小读/写单元（通常 512B 等），扇区之间有**间隙**与**扇区序号/ECC**。
- **寻道（seek）**：移动**磁头臂**到目标**磁道/柱面**；**旋转**：磁盘旋转使**目标扇区**转到磁头下。
- 磁盘块/逻辑块号由**柱面-磁道-扇区**（或线性编号）决定；磁头、盘面、柱面、扇区构成**磁盘几何**。
```
          盘面(磁头)
   ┌──────────磁道──────────┐
   │      ● 扇区            │
   │   ┌───柱面(同半径)───┐ │
   │   │                  │ │
   │   │     数据块       │ │
   │   └──────────────────┘ │
   └────────────────────────┘
```

**（2）寻道时间、旋转延迟、读取时间概念，访问时间计算方法**
- **寻道时间（Seek time）**：磁头**移动到目标磁道/柱面**所需时间（**最长、最耗时**）。
- **旋转延迟（Rotational latency）**：目标扇区**旋转到磁头下**的平均时间 = **磁盘旋转一圈时间 / 2**（平均半圈）。
- **读取（传输）时间**：从磁盘**读/写**数据块所需时间（与块大小、传输速率有关）。
- **访问（读/写）时间**：
  `磁盘访问时间 = 寻道时间 + 旋转延迟 + 传输时间`。其中**寻道时间**最重要，**磁盘调度**主要优化它。

**（3）磁盘调度算法**
- 目标：**减少寻道时间**（磁道移动最小）。
- **FCFS（先来先服务）**：按**请求到达顺序**服务；**公平简单**，但**磁头移动可能大**、性能差。
- **SSTF（最短寻道时间优先）**：每次选**离当前磁头位置最近**磁道的请求；**平均磁道移动较小**、较优；但可能**饥饿**（远处请求长期被忽略）。
- **SCAN（扫描/电梯算法）**：磁头**单向**（如向外/向内）**移动**，沿途服务该方向请求，**到边界再反向**；**无饥饿**、较好，但**两端响应慢**（边界处等待长）。
- **C-SCAN（循环扫描）**：磁头**单向**服务到**一端**，然后**快速回到另一端**（不回程服务），再**同向**扫描；**更均匀**（各磁道响应更公平），但**回程**不算服务、可能有**空走**。
- 还有 LOOK（到最远请求即反向）、C-LOOK 等变体。

**（4）磁头粘着（磁头臂粘着/Arm Sticking）**
- **概念**：当**某磁道（柱面）的请求**极多（其中**某个柱面**持续有请求），磁头**反复停在/徘徊**在该柱面**附近**，导致**其它磁道/远处请求**得不到服务——**类似饥饿**；磁头"**粘在**"某柱面附近。
- **原因**：SSTF 会被**局部密集请求**吸引；SCAN 也可能因**局部高负载**在某处滞留。
- **解决**：用 **C-SCAN/C-LOOK**（单向、回程不服务）或**改善调度**（如限制单柱面/在柱面排队等）缓解。

**记忆**：「磁盘访问=寻道+旋转延迟+传输（平均旋转=半圈）；调度：FCFS 简单、SSTF 最短（易饥饿）、SCAN 电梯（无饥饿、两端慢）、C-SCAN 单向循环扫描（更均匀）；磁头粘着=某柱面请求密集导致磁头徘徊，远处请求饥饿，用 C-SCAN 等缓解」。

**易错**：**寻道时间**是**主要优化对象**；**SSTF 易饥饿**；**SCAN 两端慢、C-SCAN 更公平**；**磁头粘着**与**饥饿**相关（不是死锁，是**调度不公平**）；**旋转延迟按半圈**算（平均）。

## 第五章 输入/输出管理

### 1. 设备分类

**核心**：按不同维度给**I/O 设备**分类：

- **按数据交换单位**：
  - **块设备**：以**块**为单位传输（磁盘、光盘），可随机访问，传输速率高。
  - **字符设备**：以**字符/字节**为单位（键盘、打印机、串口），顺序、每次一个字符。
- **按传输速率**：**低速**（键盘、鼠标）、**中速**（打印机）、**高速**（磁盘，如磁盘、网络）。
- **按使用/共享方式**：
  - **独占设备**（设备资源一次只能给一个进程，如打印机、磁带）——需**分配**，用 SPOOLING 等提高。
  - **共享设备**（多个进程可同时使用，如磁盘——微观分时、宏观共享）。
- **按数据流向**：**输入设备、输出设备、输入输出（存储）设备**。
- **按设备物理特征**：**块/字符、存储设备、网络设备**等。

**记忆**：「块 vs 字符（单位）；独占 vs 共享；速度高中低；输入/输出/存储；按传输 = 块设备 / 字符设备最常见」。

**易错**：**磁盘是块设备**（随机、块为单位）、**共享设备**（宏观共享）；**打印机是字符设备**、**独占设备**（用 SPOOLING 提高利用率）。

---

### 2. I/O 子系统层次结构

**核心**：I/O 子系统从**用户接口**到**硬件设备**分层次（现代 OS 的 I/O 软件层次）：

1. **用户层（I/O 请求用户，库/应用）**：用户通过**系统调用**（read/write）发起 I/O。
2. **用户接口层（I/O 系统调用/文件系统接口）**：提供**统一接口**（如 read/write），处理**逻辑设备名/文件**。
3. **设备无关性软件（Device-Independent I/O）**：**与设备无关**——**设备名/逻辑名→物理设备**映射、**设备分配/回收**、**缓冲管理**、**错误处理**、**块的缓存**；向上提供**统一接口**，向下调用**驱动程序**。为**所有设备统一缓冲、分配、命名**。
4. **设备驱动程序（Device Driver）**：与**具体设备**相关——把**通用请求**翻译成**设备命令**，**驱动设备控制器**，处理**中断**，管理**设备控制器寄存器/队列**。**每类设备一个驱动程序**。
5. **中断处理程序**：处理**设备完成/错误**的中断，唤醒等待进程。
6. **硬件层（设备/设备控制器）**：物理设备与**设备控制器**（含寄存器、DMA，负责**实际执行**）。

**记忆**：「用户→系统调用接口→设备无关层（命名/分配/缓冲/错误）→设备驱动（具体设备命令/中断）→中断处理→硬件（控制器）」。关键：**设备无关性软件**与**设备驱动**分界。

**易错**：**设备无关性软件**处理**逻辑名→物理、分配、缓冲、错误统一**；**设备驱动**处理**具体设备操作/控制**；设备驱动**每设备一套**；**中断处理**在驱动之后的层次。

---

### 3. 设备驱动程序的概念和特征

**概念**：设备驱动程序是一段**与具体设备/控制器**相对应的**内核代码**，负责把**设备无关层传来的通用 I/O 请求**翻译成**该设备控制器能执行的命令**，并**驱动设备、响应中断、管理设备状态**。

**特征/作用**：
- **与设备相关**：**每类设备**有**对应驱动**（驱动登记、由设备号/类型找到）。
- **屏蔽硬件差异**：向上提供**统一接口**（**设备无关层**用统一的方式调用），向下**控制设备**。
- **功能**：**初始化设备、设置设备寄存/命令、发起/控制传输（含 DMA）、处理中断、错误处理、管理缓冲/队列、关闭设备**。
- **作为内核模块/可加载**（可安装/卸载），提供**open/close/read/write/ioctl** 等操作集。
- **特点**：**复杂性**、与硬件紧密，需处理**并发/中断/同步**。

**记忆**：「驱动=与具体设备相关、把统一请求翻译成设备命令、控制设备/中断/错误/缓冲，屏蔽硬件差异；每设备一套，向上统一接口」。

**易错**：驱动**直接与设备控制器交互**（不直接干预设备机械细节之外的中断/寄存器）；**设备无关层**通过**驱动接口**调用驱动；**驱动程序**是**内核的一部分**（受保护）。

---

### 4. 磁盘缓冲技术：单缓冲、双缓冲、循环缓冲区与缓冲池

**核心**：缓冲（buffer）用于**数据在设备与内存/进程间**暂存，缓解**设备速度与 CPU/进程速度不匹配**、**减少占用、平滑 I/O**。时间计算是考点。

**（1）单缓冲的时间计算**
- **单缓冲**：只设**一个缓冲区**。数据从设备到缓冲（时间 T），再（由 CPU）从缓冲送到工作区/处理（时间 C）。设备送缓冲与 CPU 处理**不能同时**（共用缓冲）→ **顺序**。
- **处理 n 个（块）数据的总时间**：每块需要
  `时间 = max(T, C) + ... ` 由于读缓冲与处理可部分重叠，首块读后处理。
- **重点**：单缓冲处理 n 个记录：`总时间 = 或 = n×T + 处理完成时间`... 常见结论（数据读入设备到缓冲时间 T，CPU 从缓冲移到工作区+处理时间 C）：因为**读下一个与处理上一个在单缓冲下不能重叠**（共用一个缓冲），一般 `总时间 = （T + C）×? ...`——更准确：**单缓冲，读 n 次：地址/时间 = (n×(T)+处理) 或 = 读 T + 每块移动/处理 C**，通常记忆为 `处理 n 块所需时间 = T（第一块读入）+ n×C（处理+搬运）`（读与处理交替，读下一块须等处理完？）

> 为便于统一：设**从设备入缓冲 = T**、**从缓冲入进程工作区 = C**、**进程处理/占用时间 = M**。
> 标准"**单缓冲**"计算（数据块为单位，处理在数据搬运后进行）：**每次读下一块前需先处理/搬运完上一块（单缓冲冲突）**，故 `总时间 = n×T + n×C + M`（或把处理并入 C）。多数教材：**单缓冲区完成 n 个数据时间 = n×(T+C)（不含 M，若 M 与搬运可重叠按 max）**——**以零壹课件9 例题为准**：单缓冲 = 每块"读 T + 处理（搬运+计算）"**串行/部分重叠**。

**（2）双缓冲的时间计算**
- **双缓冲**：**两个缓冲区**（buffer1、buffer2）。**一个 buffer 从设备读入**（T）时，**另一个 buffer 同时被 CPU 处理**（C）→ **设备读与 CPU 处理可重叠**。
- **处理 n 块**：读第一块 T，之后**读与处理并进**：`总时间(n 块) ≈ T + n×max(T, C) 或 T + n×max(...)`,实际 `= T(首块读入) + n×max(T,C)`（C 为每块搬运+处理时间）；若 T≥C，认为总时间 ≈ T + n×T（即 约 n×T，读成为瓶颈）。
- 关键：**双缓冲读与处理重叠**，所以取 `max(T, C)`，**总时间更小**（比单缓冲快）。若**处理（C）**时间较大，双缓冲能**并行**，把处理与读重叠。

**（3）循环缓冲区**
- 用**多个缓冲区**组成**环形**（循环使用），**生产者（设备）**往空闲缓冲写，**消费者（进程）**从满缓冲读；**指针**指示读写位置。适合**批/连续**数据（流水线），多缓冲缓冲数据流。

**（4）缓冲池**
- **缓冲池**是一组**多个缓冲区**的统一管理，分为**空闲缓冲、输入缓冲队列、输出缓冲队列**，供设备输入/输出动态分配；提供**输入/输出/输入输出**三类缓冲，统一**分配、回收**，提高缓冲利用率，支持**多设备/并发**。

**记忆**：「单缓冲=一个 buffer，设备读与 CPU 处理**串行**（不能重叠），总时间 ≈ max(T,C) 叠加较少重叠；双缓冲=两个 buffer，读与处理**并行**（重叠），总时间 ≈ T + n×max(T,C)（或按 max）；循环缓冲=环形多缓冲（流水）；缓冲池=多缓冲统一管理（空闲/入/出队列）」。

**易错**：**单缓冲**读与处理**不能重叠**（共用缓冲）；**双缓冲**可**重叠**所以更优；计算时**若不重叠用加、若重叠用 max**；缓冲降低**设备与 CPU 速度差异**、减少 I/O 阻塞。（参考：零壹课件9 第 29 页「缓存例题」）

### 5. 利用物理设备名进行设备分配的具体过程

**核心**：用户（进程）提出**以物理设备名**（如 `/dev/sda1`、`打印机0`）申请设备时的**分配过程**。这是**按设备名字**直接分配，较底层。

**过程**：
1. 进程**申请**某**物理设备名**（在系统调用/打开中给出具体设备）。
2. 系统查**设备分配表**（DCT，设备控制表）——由设备**类型/名字**找到**设备**及其**分配状态**。
3. 判断**设备是否空闲**（是否有可分配）：
   - 若**独占设备且未分配** → 分配，登记到**设备分配表（DCT）**、给进程**分配设备**，返回**设备号/句柄**（可再分配**控制器/通道**）。
   - 若**已分配/共享** → 进程**阻塞/等待**（或共享则按共享方式）。
4. **逻辑设备名 → 物理设备**：若是逻辑名，需先查**逻辑设备表**映射到物理设备。
5. **分配控制器/通道**：设备分配后还需分配**设备控制器**与**通道**（DMA/通道），建立**设备-控制器-通道**连接。
6. **建立进程与设备的连接**：登记**进程打开设备表/分配表**，返回设备文件描述符；进程即可用该物理设备名进行 I/O；用完**释放**。

**记忆**：「申请物理设备名 → 查设备/设备分配表 → 判空闲（独占先分配、共享/已分配则等待或共享）→ 分配控制器/通道 → 登记连接返回设备名 → 用完释放」。

**易错**：**设备分配**涉及**设备、控制器、通道**三级；**独占设备**需**分配**（空闲才给），**共享设备**（磁盘等）按**共享/调度**方式；分配不成功则**阻塞等待**。

### 6. 利用设备无关性软件支持的逻辑设备名进行设备分配的原理

**核心**：用**设备无关性**把**进程的逻辑设备名**（如用户口中的"打印机""磁盘"）**映射**到**物理设备**，**与具体设备名解耦**（进程无需知道物理设备）。

**原理**：
- **逻辑设备表（LUT，逻辑设备名→物理设备名/驱动）**：把**逻辑设备名**映射到**对应的物理设备**与**驱动**（用**设备无关层**维护）。
- **分配过程**：进程**用逻辑设备名**（如 `printf` 用"标准输出"，打开时用逻辑名）申请 → **设备无关层**查**LUT**（逻辑名→物理设备+驱动）→ 映射到物理设备 → 再按物理设备**分配设备/控制器/通道**（见第 5 题）。
- **优点**：**与设备无关**（换设备/驱动不用改程序——"标准输入/输出"的重定向、设备独立性）、**便于分配**（SPOOLING 用逻辑设备名/虚拟设备）、**可移植**。
- 例如进程只关心"打印机输出"，系统把**逻辑设备"打印机"**映射到**任一物理打印机**（可 SPOOLING 多个进程共享）。

**记忆**：「逻辑设备名 → 设备无关层查 LUT（逻辑名→物理设备+驱动）→ 映射到物理设备 → 分配；好处=与设备无关、可重定向、可移植，用 SPOOLING/标准名共享」。

**易错**：**逻辑设备名**避免进程**绑定物理设备**（设备独立性）；**LUT** 是逻辑名到物理的映射；用户的**逻辑设备**（如"打印机"）可由系统**映射到多个物理设备**或**虚拟设备**（SPOOLING）。

### 7. I/O 控制方式和 DMA 具体过程

**核心**：I/O 控制方式决定**CPU 怎么参与**数据搬运。分为**轮询（程序直接控制）→ 中断 → DMA → 通道**四级，后两者**CPU 参与最少**。

**（1）I/O 控制方式**
- **程序直接控制（轮询）**：CPU **循环检测**设备状态寄存器（忙等）直到就绪，再读写**数据寄存器**。**CPU 忙等，效率低**。
- **中断驱动方式**：CPU 发出**读命令**后**去做别的事**（不忙等），**设备完成**时**发中断**通知 CPU，CPU 处理**中断**搬运数据。**每次一个字节/块，CPU 仍要逐次中断处理**（中断开销）。
- **DMA（直接存储器存取）方式**：**DMA 控制器**在设备与内存之间**直接传输数据块**，**完成才中断一次**；CPU 只在**开始设置**和**结束时**参与（**每块一次中断**）。
- **I/O 通道方式**：由**通道**（独立处理器）**独立执行通道程序**，完成整批 I/O，**每个通道程序结束中断一次**；CPU 参与最少。

**（2）DMA 具体过程**
1. CPU **初始化**：设置 **DMA 控制器**——**内存起始地址、传输字节数（计数）、设备/方向（读/写）、使能**。
2. CPU **发起** DMA：发**读写命令**给设备，DMA 接管总线（DMA 请求总线，CPU 让出总线/周期挪用）。
3. **DMA 传输**：DMA 控制器**直接**在**内存与设备**之间传数据（**按块/字**，读/写内存——写时 DMA 从设备读、DMA 缓冲再到内存；读时反之）。数据搬运**不经过 CPU**。
4. **传输完成**：DMA**计数器归零**（数据传输完成）→ DMA 向 CPU 发**中断**。
5. CPU **处理中断**：确认完成，处理后续（如通知进程、更新状态）——**整个块一次中断**。

**记忆**：「轮询（CPU 忙等）→ 中断（设备完成发中断、每字/块中断）→ DMA（DMA 控制器直接在内存与设备间传块、完成一次中断，CPU 只设初值与结束处理）→ 通道（通道程序、整批一次中断）；DMA：设起始地址/计数/方向 → 发起 → DMA 直传 → 计数零中断 → CPU 处理」。

**易错**：**DMA 传数据不经过 CPU**（由 DMA 控制器直接内存<->设备，可能**周期挪用**总线）；但**DMA 完成**后仍要**中断 CPU**；**DMA 每次块完成中断一次**，比中断方式（每字节）开销小。（参考：零壹课件9 第 56~58 页）

### 8. 字符设备、块设备、网络设备的用户 I/O 接口

**核心**：设备无关层向上给**不同类型设备**提供**不同的用户 I/O 接口**（系统调用形式不同）：

- **字符设备**：**逐个字符/字节**，常用**`open/close/read/write`**（每次一个字符/流），或**`getc/putc`**；如键盘、打印机、串口、终端。**顺序**访问，**无随机定位**（通常不 seek）。
- **块设备**：**以块为单位**，**随机访问**，用 **`read/write`** 按**块号**；常用 **`mmap`**（内存映射）、**`ioctl`**（控制命令）；如磁盘。**可随机**定位。
- **网络设备**：用 **`socket`** 接口（**`socket/bind/connect/listen/accept/send/recv`**），**流/报文**（TCP 流、UDP 报文），**I/O 多路复用**（`select/poll/epoll`）。
- 统一抽象：**设备文件**（如 `/dev/tty`、`/dev/sda`）通过**统一 `open/close/read/write/ioctl`** 接口访问，设备无关层按**设备类型/驱动**分派。

**记忆**：「字符设备=字节流/顺序、read/write/getc/putc；块设备=块/随机、read/write/mmap/ioctl；网络设备=socket 接口（socket 系统调用族）＋select/poll/epoll；统一映射到设备文件+普通系统调用」。

**易错**：**块设备随机/块**，**字符设备顺序/字节**；**网络设备**用 **socket 编程接口**（不是普通 read/write 直接读写文件，虽然有 send/recv）；**设备文件**把设备抽象成文件（统一 read/write）。

### 9. 不同设备访问流程

**（1）输出设备（如打印机/显示器）**
1. 用户进程调用 **write / 输出系统调用**，请求把数据输出到设备。
2. 设备无关层**分配/定位**设备，把数据放入**输出缓冲**（或驱动队列）。
3. 调用**设备驱动**：驱动向**设备控制器**发**输出命令**，把缓冲数据**送出**。
4. 设备执行输出（如打印/显示），完成后**中断**通知（或 DMA/通道完成）。
5. 中断处理**唤醒**进程，更新状态，若还有数据继续，否则**结束**。

**（2）输入设备（如键盘）**
1. 用户进程调用 **read / 输入**系统调用，请求读取数据。
2. 设备无关层**分配**设备、准备**输入缓冲**。
3. 驱动向**设备控制器**发**读命令**，**等待**设备输入。
4. 设备把数据**读入控制器缓冲**，**中断**通知 CPU；中断处理把数据**搬到**内存/缓冲。
5. **唤醒**等待进程，把读到数据**返回**（或继续读，直到用户所需字节）。

**（3）块存储设备（DMA 方式）**
1. 应用**read/write**（或 mmap）请求读写磁盘块。
2. 文件系统/设备无关层：**逻辑块号→物理块（柱面/磁道/扇区）**，分配**缓冲**。
3. 驱动设置 **DMA**（内存地址、计数、方向）→ 发起磁盘 **I/O**（寻道+旋转+传输，**调度**）。
4. **DMA** 在设备与**内存**间直接传输数据块（不经过 CPU）。
5. **DMA 完成**发**中断**，CPU 处理完成，**唤醒**进程/更新页表缓存，完成读/写。

**记忆**：「输出：write→缓冲→驱动命令→设备输出→中断→唤醒；输入：read→缓冲→驱动读命令→设备输入→中断→搬数据→唤醒返回；块设备(DMA)：逻辑块→物理块→设 DMA→寻道/旋转/传输→DMA 直传→完成中断→唤醒」。

**易错**：**输入**要**等待**设备（阻塞/中断），**输出**常**先缓冲**；**块设备**用 **DMA**（免 CPU 逐字节），中间有**磁盘调度**（寻道优化）；三类设备都要**中断**完成处理。

### 10. SPOOLING 假脱机技术

**核心**：**SPOOLING（Simultaneous Peripheral Operations On-Line 假脱机）**把**独占设备**（如打印机）改造为**共享/虚拟设备**，通过**磁盘缓冲**让**多个进程**并发地"同时"使用，提高利用率。

**（1）功能和效果**
- 把**独占设备**变成 **虚拟/共享**：用户进程**先写**到**磁盘上的假脱机文件（打印队列）**，**后台**再真正、**逐队**输出到设备。
- **效果**：**多个进程可并发"输出"**（各自写队列，互不等待），打印**串行**有序；**错峰**、提高设备利用率、**缩短进程等待**；**无需物理独占**。

**（2）组成部分**
- **输入井/输出井**（磁盘上的**假脱机缓冲**，分输入井、输出井）。
- **输入进程/输出进程**（**后台系统进程**，负责从设备输入到输入井、从输出井输出到设备）。
- **作业/请求队列**（保存待输入/输出的用户请求，如打印队列）。

**（3）输入设备和输出设备工作的具体过程**
- **输出（假脱机打印）**：
  1. 用户进程**请求输出** → 系统把输出数据**写入**磁盘**输出井**，返回（进程**不等**打印机）。
  2. **输出进程（守护）**从输出井**按队列**取数据，**真正**写到**打印机**（独占、串行）。
- **输入（假脱机输入）**：
  1. **输入进程**把设备（如读卡机/键盘等输入设备）读入的数据**写入输入井**。
  2. 用户进程**申请输入**时，从输入井**读取**（进程不等设备，设备提前读）。
- 交叉：设备**连续/后台**读写，进程**与设备解耦**（进程只管井）。

**记忆**：「SPOOLING=用磁盘井把独占设备变成共享虚拟设备；组成=输入井/输出井 + 输入/输出进程 + 队列；输出：进程写输出井→输出进程真正打；输入：输入进程先读入输入井→进程从井读；效果=并发、错峰、提高利用率」。

**易错**：**SPOOLING 常用在独占设备**（打印机）上，技术上用**磁盘缓冲 + 后台进程**；进程**其实没有真正独占设备**（写井即可），所以是**虚拟/共享**；SPOOLING 提高设备利用率、缩短等待（利用**预输入/缓输出**）。

### 11. 固态硬盘相关知识

**（1）组成部分及各部分功能**
- **SSD** 由**闪存（Flash）芯片/存储单元（NAND）**组成：**页面（page）读写单元**、**块（block）擦除单元**、**控制器（Controller）**（管理映射/损耗均衡/纠错）、**接口（SATA/NVMe）+ 缓存（DRAM/SLC cache）**。
- 功能：**控制器**把**逻辑页**映射到**物理页**（FTL 地址映射）、**磨损均衡**、**坏块管理**、垃圾回收（GC）等。

**（2）读写特点**
- **读**快（随机读也快，无寻道/旋转延迟）；**写**较慢且**页只能写一次**、**块必须先擦除**（擦除是**块**级、慢），即**写前擦（擦写放大）**。**无机械部件**、**无寻道/旋转延迟**，**低功耗、抗震、静音**。
- 写操作有**擦写**，**寿命有限**（擦写次数有限），需**磨损均衡**；读快写慢、**随机读写性能好**。

**（3）磨损均衡概念和解决方案**
- **磨损均衡（Wear Leveling）**：让**所有闪存块**被**均匀擦写**，避免**某些块写得多**而**过早损坏**，**延长寿命**。
- **方案**：**动态磨损均衡**（把新数据写到**擦写次数少**的块，同时**回收/搬运**旧数据）+ **静态磨损均衡**（把**长期不动的"冷"数据****搬到**低磨损/或有磨损余量的块，并**把冷数据所在块**用于频繁写），配合**垃圾回收（GC）**、**预留空间**。
- 最终目标：**各块擦写次数接近**，延长 SSD 整体使用寿命。

**记忆**：「SSD=闪存（页面读写/块擦除）+ 控制器（FTL 映射/垃圾回收/坏块/磨损均衡）+ 接口缓存；特点=读快、写慢（需擦块、擦写放大）、无机械、随机好但寿命有限；磨损均衡=均匀擦写各块防早坏，靠动态/静态均衡+GC+预留」。

**易错**：**SSD 写需块级擦除**（写慢、写放大），**SSD 无寻道时间**；**磨损均衡**是**让各块擦写均匀、延长寿命**（不能完全避免寿命有限）；**随机访问**比机械磁盘**快**（无旋转/寻道）。
