# 计算机网络

## 第四章 网络层

### 网络层协议细节梳理：IP、ARP、ICMP、RIP、OSPF、BGP（2026-08-18）

相关章节：第四章 网络层（数据平面协议）、第四章 网络层（控制平面路由协议）

#### 核心概念

- 网络层协议分两大类：数据平面协议（负责单个数据报的处理与转发：IP、ARP、ICMP）与控制平面协议（负责路由表计算：RIP、OSPF、BGP）
- IP 协议是网络层核心，提供无连接、不可靠、尽力交付的数据报服务
- ARP 解决"IP 地址到 MAC 地址"的解析，工作在链路层帧之上
- ICMP 是 IP 层的组成部分（不是高层协议），负责差错报告与询问
- 路由协议按作用范围分内部网关协议 IGP（RIP、OSPF）与外部网关协议 EGP（BGP）

#### 要点总结

##### 一、IP 协议

**IPv4 首部逐字段细节（固定 20 字节，最长 60 字节）**

| 字段 | 长度 | 单位 | 细节与考点 |
|------|------|------|-----------|
| 版本 | 4 bit | 无 | 4 表示 IPv4，6 表示 IPv6 |
| 首部长度 | 4 bit | 4 字节 | 字段值乘 4 才是真实字节数；最小 5（20 字节），最大 15（60 字节） |
| 区分服务 | 8 bit | 无 | 服务质量相关 |
| 总长度 | 16 bit | 1 字节 | 首部加数据总字节数，最大 65535；减去首部长度才是数据长度 |
| 标识 | 16 bit | 无 | 计数器生成；分片后各片标识相同，用于目的端重组 |
| 标志 | 3 bit | 无 | DF 置 1 禁止分片；MF 为 1 表示后面还有分片，0 表示最后一片 |
| 片偏移 | 13 bit | 8 字节 | 本片数据第一个字节在原始数据报中的位置除以 8 |
| 生存时间 TTL | 8 bit | 无 | 每经一个路由器减 1，减到 0 丢弃并回发 ICMP 时间超过报文 |
| 协议 | 8 bit | 无 | 指示数据交给谁：6 是 TCP，17 是 UDP，1 是 ICMP |
| 首部检验和 | 16 bit | 无 | 只检验首部不检验数据；每跳重新计算（TTL 每跳都变） |
| 源地址、目的地址 | 各 32 bit | 无 | 每跳不变 |

**记忆技巧**：单位最易混——首部长度单位 4 字节、总长度单位 1 字节、片偏移单位 8 字节。

![IPv4首部字段逐项讲解](<../images/零壹计网讲义4&5-网络层_p5.png>)

**IPv6（对比记忆）**：128 位地址，冒号十六进制写法；首部 40 字节固定；没有首部检验和；路由器不分片（靠 MTU 发现）；过渡用双协议栈和隧道技术。

##### 二、IP 数据报分片（高频计算题）

分片原因：链路 MTU 小于数据报长度；以太网 MTU 为 1500 字节。

出处：《零壹计网讲义4&5-网络层》第 16 页

![IP数据报分片与MTU](<../images/零壹计网讲义4&5-网络层_p16.png>)

**分片规则**：
1. 除最后一片外，每片数据部分长度必须是 8 字节的整数倍（片偏移单位是 8 字节）
2. 片偏移 = 本片数据第一个字节在原始数据报中的编号除以 8
3. 标识、源 IP、目的 IP 不变；MF 除最后一片为 0 外其余为 1；DF 为 0 才允许分片
4. 分片可以在源主机或路由器进行，重组只发生在目的主机

出处：《零壹计网讲义4&5-网络层》第 17 页

![分片标识、DF、MF、片偏移细节](<../images/零壹计网讲义4&5-网络层_p17.png>)

##### 三、ARP 地址解析协议

- 作用：把下一跳的 IP 地址解析成 MAC 地址，工作在网络层与数据链路层交界处
- 同网段流程：查 ARP 缓存，无则广播 ARP 请求帧（请求 IP 填目标 IP）；目标主机单播返回 ARP 响应；双方互相记录 IP 与 MAC 映射；缓存老化约 20 分钟
- 跨网段流程：目的主机不在本网段时，解析的是默认网关的 MAC，之后逐跳解析下一跳 MAC
- 关键结论：ARP 请求是广播帧、响应是单播帧；ARP 不能跨网段

出处：《零壹计网讲义4&5-网络层》第 22 页

![ARP广播请求与单播响应流程](<../images/零壹计网讲义4&5-网络层_p22.png>)

##### 四、ICMP 网际控制报文协议

- 封装：直接封装在 IP 数据报中，IP 首部协议字段为 1
- 差错报告报文 5 种：终点不可达、源点抑制（已弃用）、时间超过（TTL 减到 0，traceroute 原理）、参数问题、改变路由（重定向）
- 询问报文 2 种：回送请求和回答（ping 原理）、时间戳请求和回答

**不发送差错报告的 4 种情况**：
1. 对 ICMP 差错报告报文，不再发送差错报告
2. 对第一个分片之后的所有后续分片，不发差错报告
3. 对具有多播地址的数据报，不发差错报告
4. 对特殊地址（如 127.0.0.0、0.0.0.0）的数据报，不发差错报告

##### 五、RIP 路由信息协议（距离向量）

| 项目 | 细节 |
|------|------|
| 归属 | 内部网关协议 IGP，应用层协议（用 UDP 封装） |
| 封装 | UDP，端口 520 |
| 算法 | 距离向量；距离 = 跳数 |
| 距离上限 | 最大 15 跳可用，16 表示不可达；只适合小型网络 |
| 交换对象 | 只和相邻路由器交换 |
| 交换内容 | 自己的整个路由表 |
| 交换时机 | 启动后立即发 RIP 请求；之后每 30 秒周期性发 RIP 响应；180 秒收不到邻居更新，把该邻居记为不可达并删除其路由 |

##### 六、OSPF 开放最短路径优先（链路状态）

| 项目 | 细节 |
|------|------|
| 归属 | 内部网关协议 IGP，网络层协议（直接封装在 IP 数据报中，IP 协议字段为 89） |
| 算法 | 链路状态加 Dijkstra 最短路径 |
| 链路状态含义 | 本路由器与哪些路由器相邻、链路度量是多少（费用、距离、时延、带宽） |
| 交换对象 | 洪泛法，把链路状态发给 AS 内所有路由器 |
| 交换内容 | 链路状态信息（不是整张路由表） |
| 交换时机 | 链路状态变化时才洪泛；每 30 分钟刷新一次 |
| 最终效果 | 全网路由器拥有完整一致的链路状态数据库，各自独立用 Dijkstra 算最短路径 |

出处：《零壹计网讲义4&5-网络层》第 31 页

![OSPF链路状态与度量](<../images/零壹计网讲义4&5-网络层_p31.png>)

| 分组 | 名称 | 作用 |
|------|------|------|
| Hello | 问候 | 发现并维护邻居路由器可达性，选举指定路由器 |
| DBD | 数据库描述 | 向邻居给出自己链路状态数据库的摘要 |

**区域划分**（出处：《零壹计网PPT6-网络层-下》第 46 页）：大型网络把 AS 分成若干更小区域，洪泛范围限制在区域内，区域之间通过主干区域连接。工作流程：建立邻接关系（Hello）到 交换数据库摘要（DBD）到 补齐数据库（LSR、LSU、LSAck）到 Dijkstra 最短路径树到 路由表。

##### 七、BGP 边界网关协议（路径向量）

| 项目 | 细节 |
|------|------|
| 归属 | 外部网关协议 EGP，用于自治系统之间；应用层协议（用 TCP 承载） |
| 封装 | TCP，端口 179 |
| 算法 | 路径向量（AS 序列） |
| 机制 | 每个 AS 至少选一个 BGP 发言人；发言人之间先建立 TCP 连接再交换信息 |
| 交换内容 | 到某网络的完整路径（途经的 AS 序列），用序列保证无环路 |
| 目标 | 不是找最短路径，而是找可达、不绕环的路径，更强调策略 |

**四种报文**：Open 打开（建立关系）、Update 更新（通告新路径或撤销旧路径，核心报文）、Keepalive 保活（周期确认存活）、Notification 通知（报错并关闭连接）。

出处：《计算机网络笔记（湖科大版）》第 72 页

![BGP发言人与TCP 179端口](<../images/计算机网络笔记【湖科大版】_p72.png>)

##### 八、RIP、OSPF、BGP 三者对比

出处：《零壹计网讲义4&5-网络层》第 34 页

![RIP、OSPF、BGP三者对比](<../images/零壹计网讲义4&5-网络层_p34.png>)

| 对比项 | RIP | OSPF | BGP |
|--------|-----|------|-----|
| 类型 | 内部网关协议 | 内部网关协议 | 外部网关协议 |
| 算法 | 距离向量 | 链路状态加 Dijkstra | 路径向量 |
| 交换对象 | 相邻路由器 | AS 内所有路由器（洪泛） | 相邻 AS 的 BGP 发言人 |
| 交换内容 | 整个路由表 | 链路状态信息 | 路径（AS 序列） |
| 周期 | 30 秒固定 | 变化时洪泛，30 分钟刷新 | 变化时更新 |
| 封装 | UDP 520 | IP 数据报，协议号 89 | TCP 179 |
| 所属层次 | 应用层 | 网络层 | 应用层 |
| 距离度量 | 跳数，16 不可达 | 链路度量（费用时延带宽） | 路径属性加策略 |
| 适用规模 | 小型网络 | 大型网络 | 自治系统之间 |

#### 解题方法与步骤

**IP 分片计算套路**

第一步：算每片最多携带数据量 = MTU 减 20 字节首部，再向下取整到 8 的倍数
第二步：把数据部分拆片，前几片取最大携带量，最后一片取剩余
第三步：片偏移 = 该片数据首字节编号除以 8
第四步：最后一片 MF 为 0，其余 MF 为 1

**RIP 收到报文后的更新规则（四条）**

设收到相邻路由器 X 发来的 RIP 报文：
1. 预处理：把报文中所有项目的下一跳改为 X，距离全部加 1
2. 目的网络 N 不在本路由表中：直接添加该项目
3. N 在表中且原下一跳是 X：无条件替换（以最新消息为准）
4. N 在表中且原下一跳不是 X：比较距离，新的更小才更新
5. 补充：180 秒收不到 X 的更新，把 X 的路由记为不可达（16 跳）并转发出去

#### 易错提醒

> [!WARNING]
> 层次归属最常考：RIP、BGP 是应用层协议，OSPF 是网络层协议，ARP 封装在链路层帧，ICMP 属 IP 层组成。
> RIP 更新规则细节：下一跳相同无条件替换；下一跳不同才比距离。计算题常在这里设坑。
> 单位换算：首部长度乘 4、总长度乘 1、片偏移乘 8，三者不同。
> 跨网段 ARP 解析的是网关 MAC，不是目的主机 MAC。
> OSPF 只在状态变化时洪泛，不是周期性交换整表（区别于 RIP）。
> 分片最后一片数据不一定是 8 的倍数，只有"除最后一片外"必须满足。
> RIP 数字口诀：15 跳可用、16 不可达；30 秒更新、180 秒失效。

#### 例题与真题

**分片标准例题**：4000 字节数据报（含 20 字节首部）经过 MTU 为 1500 字节的以太网，如何分片？

答案：每片最多携带数据 1500 - 20 = 1480 字节（1480 是 8 的整数倍）；数据部分 3980 字节拆成 1480 + 1480 + 1020 三片。

| 分片 | 数据部分 | 片偏移 | MF |
|------|----------|--------|----|
| 第 1 片 | 1480 字节 | 0 | 1 |
| 第 2 片 | 1480 字节 | 185（1480 除以 8） | 1 |
| 第 3 片 | 1020 字节 | 370（2960 除以 8） | 0 |

**真题关联**：
- 2021 年综合题：浏览器访问 Web 服务器的完整流程，考点为 DNS 到 ARP（跨网段解析网关 MAC）到 CSMA/CD 帧的逐跳封装
- RIP 更新规则计算题：历年真题多次考查"收到邻居路由表后如何更新"的四条规则
